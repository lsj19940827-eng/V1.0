## 4. 背景

- 当前纵断面导出链路默认按渠类模板出图，围绕“渠底高程 / 渠顶高程 / 设计水位”组织。
- 当渠道级别为 `总干管 / 分干管 / 干管 / 支管 / 分支管` 等 `xx管` 级别时，实际项目需要的是管线专用模板，而不是渠类模板。
- 用户要求 `xx管` 模式下采用固定表头，并且“管中心线高程”由用户导入的轴线 DXF 直接读取。
- 仓库已经具备有压管道纵断面 DXF 导入、`longitudinal_nodes` 持久化和空间模式计算能力，本次优先复用现有链路。
- 同时，程序中已经逐步形成一套和 `xx管 / xx渠 / 有压管道同类结构` 相关的隐含规则，若不统一写明，容易在“导出层”和“预处理层”之间产生理解偏差。

## 5. 目标

- 为 `xx管` 渠道级别提供固定 5 行纵断面模板。
- “管中心线高程（米）”按导入轴线 DXF 的 `Y` 坐标解释为高程，并按节点 `MC` 桩号插值。
- `xx管` 模式只绘制“管中心线”纵断面折线，不再绘制渠底、渠顶、设计水位折线。
- `xx管` 模式允许的结构范围为：
  - `有压管道`
  - 所有名称中包含 `隧洞` 的结构
  - `定向钻`
  - `顶管`
- 普通有压管道段不显示“建筑物名称”；只有 `隧洞 / 定向钻 / 顶管` 段在“建筑物名称”行出字。
- 将程序当前已经体现的“命名 / 进出口 / 分组 / 统计”边界整理成一份可执行、可复核的文档口径。

## 6. 非目标

- 不修改主表中 `渠底高程 / 渠顶高程 / 设计水位` 的业务语义。
- 不将“管中心线高程”回写到水面线主表。
- 不重构普通渠类纵断面导出逻辑。
- 不为 `xx管` 另起一套完全独立的导出模块，优先在现有导出链路中增加清晰分支。
- 不在本 PRD 中强制要求立即统一所有主线与分支的实现细节；本文先统一文档口径。

## 7. 核心结论

### 7.1 xx管 导出层

- `xx管` 模式由渠道级别触发，不是由单条节点结构形式触发。
- `xx管` 纵断面只允许：
  - `有压管道`
  - 所有名称包含 `隧洞` 的结构
  - `定向钻`
  - `顶管`
- `xx管` 纵断面固定 5 行模板。
- `xx管` 纵断面只画 `管中心线`。
- `xx管` 纵断面中，普通 `有压管道` 不在“建筑物名称”行出字。
- `xx管` 纵断面中，仅 `隧洞 / 定向钻 / 顶管` 出现在“建筑物名称”行。

### 7.2 xx渠 / 通用预处理层

- 在 `xxpipe-batch-import-fix` 中，`定向钻 / 顶管` 已被提升为“有压管道同类”。
- 命名的 `有压管道同类` 节点会参与进出口识别和有压管道分组。
- 未命名的普通 `有压管道` 行允许存在，但会退化为“逐行独立管段”语义。
- 未命名的普通 `有压管道` 行不会跨表首尾自动配对，也不会进入“有压管道数据组”弹窗流程。

### 7.3 面向使用者的口径

- `xx渠` 中的普通 `有压管道` 应尽量命名。
- `xx管` 中的普通 `有压管道` 不应在纵断面“建筑物名称”行显示名称。
- `xx管` 中真正需要命名并分进出口的是：
  - `隧洞`
  - `定向钻`
  - `顶管`

## 8. xx管 纵断面导出规则

### 8.1 触发条件

- 当 `ProjectSettings.channel_level` 属于以下集合时，纵断面导出进入 `xx管` 模式：
  - `总干管`
  - `分干管`
  - `干管`
  - `支管`
  - `分支管`
- 建议以统一辅助函数维护该判断，避免字符串比较分散在多个导出函数中。

### 8.2 允许结构与校验

#### 8.2.1 允许结构

`xx管` 模式允许以下结构参与导出：

- `有压管道`
- 任意 `隧洞*`
- `定向钻`
- `顶管`

#### 8.2.2 严格校验

- 导出前检查所有有效节点。
- 只要混入不在允许列表中的结构，就禁止按 `xx管` 模式导出。
- 错误提示必须列出冲突行或冲突结构，不能只给出泛化的“导出失败”。

### 8.3 固定 5 行模板

`xx管` 模式不再使用当前可配置的 11 项纵断面行，而是固定为：

1. 建筑物名称
2. IP点名称
3. 里程桩号（千米+米）
4. 管中心线高程（米）
5. 管材（管径/米）

### 8.4 各行内容规则

#### 8.4.1 建筑物名称

- 普通 `有压管道` 段默认不出字。
- 只有 `隧洞 / 定向钻 / 顶管` 这些特殊段出字。
- 文本按整段居中。
- 推荐显示文案为“建筑物名称 + 结构简称”，例如：
  - `1#洞段隧洞`
  - `穿路段定向钻`
  - `顶管`

#### 8.4.2 IP点名称

- 复用当前 IP 名称生成逻辑。
- 保持现有 `IP + 建筑信息` 的文案风格。

#### 8.4.3 里程桩号（千米+米）

- 复用 `ProjectSettings.format_station()`。
- 保持现有前缀与格式化规则。

#### 8.4.4 管中心线高程（米）

- 对每个导出节点按 `MC` 桩号到轴线上取值。
- 取值顺序：
  - 命中导入节点：直接取节点高程
  - 落在线段内：线性插值
  - 落在竖向圆弧段内：按圆弧参数插值
- 保留 3 位小数。
- 只要任一节点取值失败，本次导出应整体中止。

#### 8.4.5 管材（管径/米）

- 每段居中出一次。
- 即便当前段属于 `隧洞 / 定向钻 / 顶管`，第 5 行仍只写承压管材质和管径。
- 默认紧凑格式：
  - `球墨铸铁管 DN1200`
  - `钢管 DN1000`
  - `玻璃钢夹砂管 DN800`

### 8.5 轴线 DXF 规则

#### 8.5.1 导入对象

- 用户导入的是“管中心线 / 轴线”纵断面 DXF。

#### 8.5.2 二维 AutoCAD 口径

- `X = 桩号`
- `Y = 高程`

#### 8.5.3 桩号对齐

- 采用“起点自动对齐”：
  - 取 DXF 第一点评估的起点 `X`
  - 自动对齐到该管道进口 `MC` 桩号

#### 8.5.4 覆盖范围规则

- 轴线覆盖范围必须覆盖到所有需要导出的节点。
- 任一节点桩号落在导入范围外，就中止导出并列出缺失节点。
- 不允许留空导出，不允许端点外推。

### 8.6 数据作用域

- 导入的轴线纵断面数据只服务 `xx管` 导出。
- 不回写水面线主表。
- 不改变现有水力计算字段。
- 继续复用现有 `longitudinal_nodes` 持久化字段。

### 8.7 主折线绘制规则

- 普通渠类模式：保持现状。
- `xx管` 模式：
  - 仅绘制“管中心线”纵断面折线。
  - 不绘制 `渠底高程线 / 渠顶高程线 / 设计水位线`。

### 8.8 实现约束

- 复用已有 `PressurePipeConfigDialog._import_longitudinal_dxf()` 与 `DxfParser.parse_longitudinal_profile()` 能力。
- 复用现有 `longitudinal_nodes` 持久化能力。
- 单独维护 `xx管` 固定模板，不污染普通渠类可配置行定义。
- 合并 DXF 与单独 DXF 必须共用同一套 `xx管` 出图口径。

## 9. 程序现状补充规则

### 9.1 哪些结构被当作“有压管道同类”

按分支已实现规则，以下结构进入“有压管道同类”语义：

- `有压管道`
- `定向钻`
- `顶管`

这层语义的含义不是“在图上都叫有压管道”，而是：

- 会被标记为 `is_pressure_pipe=True`
- 会参与有压流建筑物相关逻辑
- 会复用有压管道计算与配置链路的一部分能力

同时，程序会保留原结构类型文本，不会把 `定向钻 / 顶管` 统一改写成 `有压管道`。

### 9.2 名称与进出口判定

#### 9.2.1 命名的有压管道同类

- 当节点属于 `有压管道 / 定向钻 / 顶管` 且名称非空时：
  - 程序会按“同名 + 结构类别”统计出现次序
  - 第一次出现记为 `进`
  - 最后一次出现记为 `出`
  - 中间节点记为普通断面

#### 9.2.2 未命名的普通有压管道

- 当节点结构为普通 `有压管道` 且名称为空时：
  - 程序允许保留空名称
  - 该行会被视为“逐行独立管段”
  - 不跨表首尾配对
  - `in_out` 会被置为普通断面，而不是自动判成 `进/出`

这意味着：未命名有压管道并非完全不可用，但它不会拥有完整的“成组有压管道”行为。

#### 9.2.3 隧洞 / 定向钻 / 顶管

- `隧洞` 仍属于需要名称和进出口的特殊建筑物。
- `定向钻 / 顶管` 在分支实现里也已进入“需要按组识别”的口径。
- 从当前代码和测试意图看，这三类应视为“需要命名并分进出口”的对象。

### 9.3 输入校验中的名称规则

按 `xxpipe-batch-import-fix` 当前实现：

- 允许空名称：
  - `明渠-梯形`
  - `明渠-矩形`
  - `明渠-圆形`
  - `有压管道`
- 不允许空名称：
  - `倒虹吸`
  - `隧洞`
  - `渡槽`
  - `矩形暗涵`
  - `定向钻`
  - `顶管`

因此，对用户操作的推荐应写成：

- `xx渠` 中普通 `有压管道`：尽量命名
- `定向钻 / 顶管 / 隧洞`：应命名

### 9.4 有压管道水力计算入口规则

按 `xxpipe-batch-import-fix` 当前实现：

- 只要表中存在 `有压管道同类` 节点，按钮就保持可点击。
- 但真正能进入计算弹窗还要满足两类前置条件：
  - 拓扑已经准备好，或已插入渐变段
  - 至少存在一个“带名称的有压管道数据组”

若只检测到匿名有压管道行，程序当前提示口径是：

- 这些行按逐行损失计算
- 无需先执行“有压管道水力计算”

若表中没有形成任何命名组，程序会提示：

- `未找到有压管道数据组`

### 9.5 断面汇总与建筑物特性统计

按主线实现与回归夹具意图：

- `xx管` 回归主样例按 3 个流量段组织：
  - 普通有压管道 + 隧洞
  - 普通有压管道 + 定向钻
  - 普通有压管道 + 顶管
- 断面汇总 / 建筑物特性统计列的预期口径为：
  - 只统计 `隧洞 / 定向钻 / 顶管` 的座数与长度
  - 普通 `有压管道` 不记入建筑物特性列

因此，“普通有压管道是承压主体”，“隧洞 / 定向钻 / 顶管是需要单列统计的穿越型建筑物”是当前程序意图的一部分。

## 11. 已知不一致与解释口径

### 11.1 通用 special-structure 口径 与 xx管 导出口径并不完全一致

- 主线通用函数中，`有压管道` 仍被视为特殊建筑物的一类。
- 这会影响：
  - 通用纵断面建筑物名称段划分
  - 平面建筑物名称导出
  - 部分依赖 `进/出` 的逻辑
- 但 `xx管` 专用导出层已经额外收紧为：
  - 普通 `有压管道` 不显示建筑物名称
  - 只显示 `隧洞 / 定向钻 / 顶管`

因此，本文将两者解释为：

- 通用层：偏“数据识别 / 特殊建筑物处理”
- xx管 导出层：偏“最终图面表达”

### 11.2 分支已把 定向钻 / 顶管 纳入有压管道同类，但主线尚未完全全域统一

- 分支代码已在预处理、分组提取、共享数据透传、批量占位行等环节把 `定向钻 / 顶管` 纳入“有压管道同类”。
- 主线 `xx管` 导出与测试也已支持它们出现在导出链路中。
- 但若仅看当前 `master` 某些通用函数，仍可能看到以 `有压管道` 为主语的旧表述。

本文口径采取：

- 在需要判断“是否走承压管逻辑”时，把 `定向钻 / 顶管` 与普通有压管道并列描述。
- 在需要判断“图面建筑物名称是否显示”时，把 `定向钻 / 顶管` 与 `隧洞` 归为命名建筑物。

## 12. 建议写入团队共识的简化规则

1. `xx管` 纵断面里，普通 `有压管道` 不命名，也不靠图面区分进出口。
2. `xx管` 纵断面里，只有 `隧洞 / 定向钻 / 顶管` 需要命名，且这三类按进出口组织。
3. `xx渠` 或通用表3处理中，普通 `有压管道` 最好命名；不命名虽然允许，但只会按逐行独立管段处理。
4. `定向钻 / 顶管` 在程序语义上已经属于“有压管道同类”，但在图面和统计上仍保留各自工艺名称。

## 13. 验收要点

- `xx管` 模式下表头固定为 5 行。
- 结构校验允许 `有压管道 / 隧洞 / 定向钻 / 顶管`，其余拦截。
- 建筑物名称仅在 `隧洞 / 定向钻 / 顶管` 段出现。
- 管中心线高程按轴线 DXF 插值得到。
- 导入范围不足时禁止导出。
- 图上只画中心线，不画渠底、渠顶、水位三线。
- `xx渠` 中普通有压管道的文档口径明确为“尽量命名”。
- `xx管` 中普通有压管道的文档口径明确为“不在建筑物名称行命名”。
