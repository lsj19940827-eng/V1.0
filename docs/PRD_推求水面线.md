## 一、模块概述

### 1.1 模块定位

推求水面线模块用于计算渠道沿线各节点的水面高程，是渠系工程水力设计中的核心计算环节。模块接收渠道中心线平面坐标、各建筑物断面参数和起始水位，输出沿程水位、渠底高程、渠顶高程、各类水头损失及桩号等完整成果。

这个模块在整条业务链中的职责非常明确：

- 向上承接批量计算提供的断面参数、流量和结构信息。
- 向内完成几何计算、渐变段处理、水力递推和结果组织。
- 向下为 CAD、Excel、Word 导出，以及土石方计算等后续环节提供统一结果。
- 对倒虹吸和有压管道采用“外部专用模块计算总损失，本模块统一纳入水位递推”的协作方式。

### 1.2 核心能力

- 平面几何计算：转角、切线长、弧长、桩号体系。
- 多建筑物类型的沿程损失、局部损失、弯道损失和渐变段损失计算。
- 倒虹吸水头损失外部导入，并联动倒虹吸水力计算模块。
- 有压管道水头损失外部导入，并联动有压管道水力计算模块。
- 渐变段与明渠段的自动识别、补段与插入。
- 多流量段支持，包括共享当前流量段的只读查看组，以及设计流量和加大流量列表的同步维护。
- 成果导出，覆盖 Excel、Word、DXF，包括纵断面表格、断面汇总、IP 坐标表和全部合并导出。

### 1.3 输入、输出与协作边界

**输入**

- 渠道中心线坐标：节点 `X / Y` 与转弯半径。
- 断面参数：底宽、边坡、直径、半径、水深、糙率、底坡等。
- 项目设置：渠道名称、渠道级别、起始水位、起始桩号、设计流量、加大流量、渐变段系数。
- 外部水头损失：倒虹吸和有压管道的专用计算结果。

**输出**

- 节点级成果：水位、渠底高程、渠顶高程、流速、面积、湿周、水力半径。
- 损失成果：沿程、弯道、渐变段、局部、过闸、倒虹吸/有压管道总损失，以及累计总损失。
- 几何成果：IP、BC、MC、EC 桩号，转角、切线长、弧长。
- 导出成果：Excel、Word、DXF、TXT、bzzh2 命令、建筑物名称上平面图文本。
- 导出数据层会额外生成：`centerline_draw_segments`（优先按 route 级 `raw_profile_polyline` 裁切后的原线画线）与 `profile_breakpoint_records`（工程折点接口预留/后续 coverage 数据口）；现有 `centerline_records` 继续保留给平面桩号文字取值。

**协作边界**

- 倒虹吸和有压管道的“总水头损失”由外部专用模块负责求解，本模块只负责提取、回写和参与递推。
- 渐变段与明渠段插入的详细算法单列在 `docs/PRD_渐变段与明渠段插入算法.md`，本 PRD 只保留与主链路直接相关的接口约定和行为边界。

## 五、计算内核

本章只描述水面线模块自身负责的计算职责。整体顺序可以理解为：先组织节点与断面输入，再处理几何与渐变段，再执行水力递推，最后形成导出结果。

### 5.1 平面几何计算（GeometryCalculator）

输入每个节点的 `(x, y, turn_radius)`，逐节点计算：

| 字段 | 公式 / 规则 |
|------|-------------|
| 方位角 | $\alpha = \arctan2(\Delta X, \Delta Y)$（测量方位角） |
| 转角 | $\Delta\alpha$（相邻方位角差，取 0~180°） |
| 切线长 | $T = R \times \tan(\alpha / 2)$ |
| 弧长 | $L = R \times \alpha$（弧度） |
| BC / MC / EC 桩号 | $S_{BC} = S_{IP} - T$，$S_{MC} = S_{BC} + L / 2$，$S_{EC} = S_{BC} + L$ |
| 复核弯前 / 弯后 / 总长度 | 检查前后 IP 夹直线长度是否合理 |

自动跳过以下两类行，避免对插入行重复计算平面线形：

- 渐变段行：`is_transition=True`
- 自动插入明渠行：`is_auto_inserted_channel=True`

### 5.2 水力计算（HydraulicCalculator）

#### 5.2.1 结构高度估算

| 结构类型 | 结构高度来源 |
|---------|-------------|
| 明渠-圆形 / 隧洞-圆形 | 直径 `D` |
| 隧洞-马蹄形 | `2 × r`（等效直径） |
| 明渠-U形 | `section_params['h_prime']` |
| 其他（梯形 / 矩形 / 渡槽 / 暗涵） | 必须从批量计算导入 |
| 倒虹吸 / 有压管道 | 不计算渠顶高程，直接跳过 |

#### 5.2.2 各结构的水深、面积与湿周

- 圆形断面采用角度积分精确算法。
- 马蹄形隧洞按标准Ⅰ型 / Ⅱ型分别采用对应解析公式。
- 其余断面均使用常规解析式。

#### 5.2.3 沿程水头损失

有效计算长度 $L_{eff}$ 为两节点 `MC` 桩号差，扣除渐变段长度和两端弧长各半：

$$L_{eff} = \Delta S_{MC} - L_{tr} - \frac{L_{arc,1}}{2} - \frac{L_{arc,2}}{2}$$

**主方法（优先）**：已知底坡 $i$ 时，直接采用：

$$h_f = i \times L_{eff}$$

**备用方法（底坡缺失时）**：采用曼宁公式，并取两端平均水力坡降：

$$J = \frac{n^2 v^2}{R^{4/3}}, \quad h_f = \frac{J_1 + J_2}{2} \times L_{eff}$$

#### 5.2.4 弯道水头损失

$$h_w = \frac{n^2 \cdot L_{arc} \cdot v^2}{R^{4/3}} \times \frac{3}{4}\sqrt{\frac{B}{R_c}}$$

规则如下：

- 仅当节点 `arc_length > 0` 时计算，也就是该节点确实存在平面转弯。
- $R_c$ 只取当前节点自己的 `turn_radius`。
- 若该值为 `0` 或留空，则本节点按“无转弯半径”处理，不再回退使用顶部 `settings.turn_radius`。

#### 5.2.5 局部水头损失

| 结构类型 | 计算方式 |
|---------|---------|
| **倒虹吸** | 直接返回外部导入的总水头损失（`inverted_siphon_losses[name]`），不再单独计算弯管或沿程 |
| **有压管道** | 直接返回外部导入的总水头损失（`pressure_pipe_losses[name]`），处理逻辑与倒虹吸一致 |
| 闸类（分水闸 / 节制闸等） | 返回 `0`；过闸损失在 `head_loss_gate` 中单独计算 |
| 其他 | 查表 `LOCAL_LOSS_COEFFICIENTS`，并按进出口标识选择进口或出口系数 |

#### 5.2.6 水位递推公式

$$Z_i = Z_{i-1} - h_f - h_j - h_w - h_{tr}$$

$$h_{total,i} = h_f + h_j + h_w + h_{reserve} + h_{gate} + h_{siphon}$$

其中：

- $h_{tr}$ 表示从上一节点到当前节点之间所有渐变段损失之和，按累计值参与递推。
- $h_{siphon}$ 同时包含倒虹吸和有压管道的水头损失，两者都写入 `head_loss_siphon` 字段。
- 对闸类节点，递推公式退化为 $Z_i = Z_{i-1} - h_{gate}$，仅扣除过闸损失。
- 首节点水位 $Z_0$ 直接来自用户输入的起始水位，不参与递推计算。

#### 5.2.7 有压流建筑物出口渠底高程（公式 10.3.6）

$$H_d = H_u + h_u - h_d - \Delta Z$$

参数定义如下：

- $H_u$：上游渠道末端渠底高程
- $h_u$：上游渠道设计水深
- $h_d$：下游渠道设计水深
- $\Delta Z$：倒虹吸 / 有压管道水损与渐变段损失之和

该公式统一适用于倒虹吸和有压管道的出口节点。

### 5.3 渐变段与明渠段插入算法

渐变段与补段的完整算法定义单列在 `docs/PRD_渐变段与明渠段插入算法.md`。本 PRD 只保留与水面线主链路直接相关的落地边界，确保开发协作时能明确知道本模块“依赖什么、写回什么、如何和 UI 对齐”。

当前主链路已明确的行为边界如下：

- donor 候选当前支持“明渠或暗渠（已落地为矩形暗涵）”，不再局限于明渠。
- donor 家族首选规则为：仅当空隙两端真实结构都属于矩形暗涵场景时优先暗渠，否则优先明渠。
- donor 整体排序沿用 `同段首选 -> 同段非首选 -> 跨段首选 -> 跨段非首选`。
- 插入补段时，矩形暗涵按内部统一类型 `矩形暗涵` 创建，并保证后续链路可直接读取 `B / H_total / water_depth / roughness / slope_i / structure_height` 等字段。
- 前台无 donor 的位置必须转为人工确认，不再通过几何规则自动兜底编造参数。
- `available_length` 统一表示“当前可用长度”；若长度不足，则固定记为 `0.0`。
- 渐变段长度在插入判断和详情补建两条链路上已统一应用同一套规则解析：先算公式/规范值，再套组合规则，最后才叠加单条覆盖与里程压缩。

**渠道糙率导入交互（当前实现）**

- 从批量计算同步到表3时，系统只收集明渠 / 渡槽 / 隧洞 / 暗涵 4 类结构的糙率 `n`，作为顶部“渠道糙率”的候选值；倒虹吸、有压管道、闸类和其他非渠道结构不参与这次统一选择。
- 若候选糙率全部一致，系统不弹窗，直接把该值写入顶部“渠道糙率”，并保持本次导入的对应普通渠道行与该值一致。
- 若候选糙率不一致，系统会在**同步到表3前**弹出“选择渠道糙率”窗口，显示候选值及出现次数；用户点击“确定”后，所选值会同时写入顶部“渠道糙率”和本次导入的对应普通渠道行。
- 用户点击“取消”时，系统保留当前各行原始糙率，不自动回退到出现次数最多的值。
- 这次统一选择只影响表3和后续水面线计算，不回头修改已经完成的表1断面结果。

**自动转弯半径规则（`_auto_calc_turn_radius`）**

| 结构类型 | 控制尺寸 | 公式 |
|---------|---------|------|
| 隧洞（圆形 / 马蹄形） | 洞径 `D = 2r` | `R ≥ D × 5` |
| 隧洞（圆拱直墙 / 矩形类） | 洞宽 `B` | `R ≥ B × 5` |
| 明渠（梯形 / 矩形） | 水面宽 `B + 2mh` | `R ≥ 水面宽 × 5` |
| 明渠-U形 | 水面宽（按弧区 / 直线段分支计算） | `R ≥ 水面宽 × 5` |
| 渡槽 | 连接明渠渠底宽 `B` | `R ≥ B × 5` |
| 矩形暗涵 | 涵宽 `B` | `R ≥ B × 5` |
| 倒虹吸 / 有压管道 | — | 跳过，不参与自动计算 |

遍历所有节点后，系统会取各结构“最小允许半径”中的最大值，并通过弹窗展示逐节点推算过程；用户确认后再写入 `turn_radius_edit`。

若没有任何节点能提供可计算依据，则“自动”按钮回填统一默认值 `20m`。

**顶部转弯半径栏位显示规则**

- 所有真实导入行的正数转弯半径完全一致：顶部栏位显示这个统一值。
- 存在不同正数转弯半径的混合值：顶部栏位保持空白。
- 全部为空或 `0`：顶部栏位保持空白。

**“应用”按钮规则**

- 允许输入 `0` 或正数；不允许负数和无效文本。
- 点击后先弹出确认提示，明确告知会覆盖所有真实导入行。
- 自动插入的渐变段和补段不参与覆盖。
- 如果希望不同的行使用不同转弯半径，建议在导入 Excel 前就在 Excel 中分别填好。

### 7.1.1 当前实现同步说明：有压流断面汇总按“建筑物 + 流量段”绑定（2026-03-13）

- `cad_tools.py` 当前实现会先从节点中提取倒虹吸 / 有压管道的 `name`、`flow_section`、`display_name`、默认 `DN_mm` 和 `structure_kind`，再与用户缓存参数合并。
- `custom_pressurized_pipe_params` 的项目缓存格式已升级为对象列表，字段包括 `name / flow_section / display_name / pipe_material / DN_mm / structure_kind`；旧三元组格式 `(name, material, dn)` 读取时会自动迁移。
- 倒虹吸导入链路会保留 Excel / 表1 的 `pipe_material`，并沿“批量结果 -> 共享结果 -> 表3节点 -> 参数窗口缓存”继续透传；因此 `导出全部DXF` 与 `生成断面汇总表` 弹窗都会优先回显用户原始输入的倒虹吸材质。
- 有源数据场景下，倒虹吸参数窗口仅锁定 `DN`，不再锁定材质；若节点里未提供倒虹吸材质，则窗口默认显示 `球墨铸铁管`，但用户仍可在导出前改成其他支持项。
- 倒虹吸断面汇总支持段级 `pipe_material` 推导默认糙率；当前 `SIPHON_MATERIALS` 新增 `HDPE管 -> n=0.010`。若段级已经有显式 `n`（来自 Excel / 表3 节点），则继续优先使用显式 `n`，不会被材质默认值覆盖。
- 旧缓存迁移规则如下：
  - 若旧缓存名称只匹配到 1 个实际流量段，则直接迁移到该实体行。
  - 若同名建筑物跨多个流量段，则按名称复制到所有匹配实体行。
  - 若已存在精确的“名称 + 流量段 + 结构类型”缓存，则优先使用精确命中值。
- 若某倒虹吸 / 有压管道缺少可解析的 `flow_section`，参数对话框会明确提示该条目被跳过；本次配置与导出均不为其生成汇总行。

### 7.1.2 当前实现同步说明：明渠断面汇总按“结构类型 + 流量段”聚合（2026-03-28）

- `导出全部DXF` 与 `生成断面汇总表` 当前都会优先基于当前表格快照构建节点后再汇总，不是把表3当前可见行逐行直接抄写到 DXF。
- 节点进入断面汇总前，会先按结构类型归类，再按流量段索引归桶；`明渠-矩形`、`明渠-梯形`、`明渠-U形`、`明渠-圆形/圆管涵` 等分别独立汇总。
- 同一“结构类型 + 流量段”桶内，`Q / n / slope_inv / B / m / R / H1 / V` 等字段采用“首个有效值保留”策略；后续节点仅在对应字段尚未取得有效值时补值，不覆盖已记录值。
- 因此，同一流量段内若前面先出现 `明渠-矩形 + 1/2000`，后面再出现 `2.2、4.8、15.4、19.7` 等更陡坡降的矩形明渠，断面汇总表仍只输出该流量段 1 行矩形明渠，且坡降沿用先出现的 `1/2000`。
- 上述表现是“按流量段聚合 + 首个有效值保留”共同造成的当前实现，并不存在“专门只保留 `1/2000` 矩形明渠”的特殊判断。

## 九、跨模块集成

### 9.1 从批量计算导入（SharedDataManager）

联动顺序如下：

1. 批量计算完成后，通过 `SharedDataManager.register_batch_results()` 写入共享断面参数。
2. 水面线面板点击“从批量计算导入”后，调用 `_import_from_batch()`。
3. 导入动作会自动完成以下事情：
   - 同步渠道名称、级别、起始水位、流量等基础设置。
   - 同步设计流量后，当前流量段回到第一段，并立即按最新设计流量整体重算加大流量；主界面两列保持同一当前段显示。
   - 自动填充节点表中的底宽、水深、糙率、底坡、边坡等参数。
   - 渠道糙率候选只来自明渠 / 渡槽 / 隧洞 / 暗涵 4 类结构；倒虹吸、有压管道、闸类和其他非渠道结构不进入这次统一选择。
   - 若这些候选糙率存在多个值，系统会在**同步到表3前**弹出“选择渠道糙率”窗口；确认后，所选值同步写入顶部“渠道糙率”和本次导入的对应普通渠道行，取消则保留各行原值。
   - 若候选糙率本来就一致，系统不弹窗，直接按该值同步顶部栏位和本次导入的对应普通渠道行。
   - 对有压管道节点标记 `is_pressure_pipe=True`，并传递管材、管径等参数。
   - 若结构类型为 `明渠-复式梯形`，额外保留 `m1 / B1 / m2 / B2 / m3 / h1` 六个隐藏参数，供后续开放渠道几何与水力计算使用。
   - 触发几何重算，即 `_recalculate_geometry_impl`。
   - 按真实导入行的转弯半径状态刷新顶部栏位：统一正数时显示该值，混合值或全空/`0` 时保持空白。

> 说明：导入动作不会自动把推荐转弯半径写入顶部栏位，也不会自动把顶部栏位的值回填到各行；每一行继续以自己的导入值为准，只有用户点击“应用”后才会统一覆盖。

### 9.2 倒虹吸水力计算（MultiSiphonDialog）

联动链路如下：

1. 点击“倒虹吸水力计算”，调用 `_open_siphon_calculator()`。
2. 通过 `SiphonDataExtractor` 从节点表提取倒虹吸分组。
3. 打开 `MultiSiphonDialog` 时传入：
   - `siphon_groups`
   - 倒虹吸转弯半径倍数 `n`，固定取 `DEFAULT_SIPHON_TURN_RADIUS_N=3.0`
   - 回调函数 `import_losses_callback`
4. 倒虹吸计算完成后，回调写入：
   - `node.head_loss_siphon`：总水头损失
   - `node.section_params["D"]`：管径，供后续几何重算使用

`SiphonDataExtractor` 当前的关键行为如下：

- `_extract_plan_segments()` 用于提取平面弯管段。转角来自 `node.turn_angle`，即 `geometry_calc` 基于坐标 `XY` 自动计算的结果。为过滤浮点噪声，**转角 < 0.1° 时不生成弯管段，视为直线通过**。
- `_extract_plan_feature_points()` 用于提取空间合并所需的 IP 特征点。同样地，若转角 < 0.1°，则 `turn_type` 记为“无”，不参与空间弯道计算。
- 倒虹吸面板本身若通过 DXF 导入平面段，则角度来自真实几何，不经过 `SiphonDataExtractor`，因此不受该阈值限制。
- `v₁ / v₃` 与 `v₁加大 / v₃加大` 当前实现采用统一 donor 顺序：`同流量段上游 -> 同流量段下游 -> 跨流量段上游 -> 跨流量段下游`。donor 候选范围已从“仅明渠”扩展到“明渠或暗渠（当前落地为矩形暗涵）”；隧洞不纳入 donor。详细规则见 `PRD_渐变段与明渠段插入算法.md` §12.6。

当前实现同步说明（2026-03-16）：

- 同流量段命中 donor 后，直接复用其 `velocity / velocity_increased` 与邻接断面参数。
- 跨流量段明渠仍沿用“原尺寸试算 + 必要时自动重设计”。
- 跨流量段暗渠则先按原 `B / H` 试算，失败后保留原底宽 `B` 并自动增大高度 `H` 后重算；若仍失败，则状态保持为 `missing`，并要求人工确认，不自动编造默认流速。
- `MultiSiphonDialog` 在窗口初始化后只弹出 1 条“流速来源提醒”汇总提示，文案统一使用“邻接断面流速”口径，并区分“同段复用”“跨段借型并重算”“借用后重定邻接断面”“仍未找到可用邻接断面”。
- 提示中会展示 donor 类型（明渠 / 暗渠）、来源流量段、扫描方向与重设计方式，方便用户直接核对。

### 9.3 有压管道水力计算

联动链路如下：

1. 点击“有压管道水力计算”，调用 `_open_pressure_pipe_calculator()`。
2. 通过 `PressurePipeDataExtractor.extract_pipes(nodes, settings)` 从节点表提取有压管道分组，支持多行模式（进口 + IP 点 + 出口）。
3. 对每条有压管道：
   - 根据是否存在纵断面数据，选择平面模式或空间模式。
   - 调用 `calc_total_head_loss()` 或 `calc_total_head_loss_with_spatial()` 计算总水头损失。
   - 可选执行灵敏度分析，例如球墨铸铁管 `f` 上下限对比。
4. 计算结果回写：
   - 命名整组结果仍可写入 `node.head_loss_siphon`，与倒虹吸共用同一列。
   - 若属于 `xx渠` 末尾连续承压中的命名 `有压管道 / 定向钻 / 顶管` 尾段，或属于所有 `xx管` 连续承压链中已真正进入承压链的命名 `有压管道 / 定向钻 / 顶管`，则先拆成逐行成员，并把逐段结果写入 `pressure_pipe_window_override`；表3列38、总损失、累计损失和水位统一按逐段值递推。
   - 拆分后的父命名组继续保留窗口汇总结果，但 `writeback_enabled = False`，不再参与表3正式累计。
   - 持久化到 `PressurePipeManager`。
   - 详细计算过程追加到 `detail_text`。
5. 更新有压管道参数芯片 `pressure_pipe_roughness_chips`，展示各管道的管材与 `f / m / b` 系数。

### 9.4 向土石方计算模块提供数据

水面线面板通过 `calculated_nodes` 对外暴露计算结果。土石方模块通过父链访问 `water_profile_panel.calculated_nodes`，提取：

- `station_MC`
- `bottom_elevation`

作为设计纵坡输入。提取时跳过 `is_transition=True` 的渐变段行。

## 十一、设计决策记录

### DDR-1：倒虹吸水头损失不在水面线内核中单独计算

倒虹吸涉及多管段、弯管和渐变段等复杂因素，统一交由倒虹吸专用模块 `MultiSiphonDialog` 计算总水头损失后回写。水面线内核中的 `calculate_local_loss` 对倒虹吸节点直接返回外部导入值，不再重复走局部损失公式。

### DDR-2：倒虹吸与有压管道节点不在本模块内计算弯道水头损失（`hw = 0`）

弯道水头损失仅在 `arc_length > 0` 时触发。实际使用中，倒虹吸和有压管道在水面线节点表里以黑箱整体出现，没有显式平面转角，因此 `arc_length = 0`、`hw = 0`。这样可以确保不与各自专用面板中已包含的弯管损失重复计算。

### DDR-3：`siphon_turn_radius_n` 不对外暴露 UI

该参数只在有压流几何辅助计算时供内部使用，属于内部参数。固定使用常量 `3.0` 已满足需求，无需用户手动设置。

### DDR-4：有压管道与倒虹吸共用 `head_loss_siphon` 列

命名整组有压管道的总损失仍回写到 `head_loss_siphon` 字段，也就是表格中的 col 38“倒虹吸水头损失”列；但 `xx渠` 末尾连续承压中的命名尾段若已拆成逐行成员，则改为通过 `pressure_pipe_window_override` 保存逐段结果，并继续占用同一列做显示。原因是界面列不变，但逐段场景必须避免旧整组值再次干扰总损失和水位递推。

若命名尾段出口行在旧工程恢复或静默重算时，`head_loss_siphon` 已被清空、但列38对应的 `_pressure_pipe_display_loss` 仍保存着本段损失，则系统必须继续把这笔显示值正式计入总损失、累计损失和水位递推；它不是纯展示文本。

对 `pressure_pipe_window_override` 驱动的逐行承压成员，col 38 展示值、总损失、累计总损失和水位递推必须统一以同一份覆盖结果重建，不能出现“col 38 有值、但总损失和累计仍按旧整组口径”的分裂。

表3第38列的人工采用值必须独立保存为 `pressure_pipe_loss_override_m`，显示优先级固定为“人工采用值 > 当前行显示用结果 > 原始计算/兼容回填结果”。人工采用值参与总损失、累计总损失和水位递推，但不覆盖 `pressure_pipe_window_override` 或命名承压组隐藏结果，因为详情弹窗仍需保留原始计算依据，并支持用户随时恢复计算值。

压力管道特性表中的 `渠首水位 / 渠末水位` 仍优先按当前流量段 `upstream_row_index / target_row_index` 指向的有压边界节点读取；只有跨流量段且边界本身连续时，上一段 `渠末水位` 与下一段 `渠首水位` 才会共用同一个切段点水位。单流量段 `xx管` 不再额外回退整条连续承压链的首末水位。

### DDR-5：有压管道渐变段设置复用倒虹吸设置

有压管道的渐变段形式和 `ζ` 系数，复用 `ProjectSettings` 中的 `siphon_transition_*` 字段。原因是两者都依据 GB 50288 附录 L 表 L.1.2。

### DDR-6：坐标计算路径的弯头转角必须加 0.1° 阈值过滤，DXF 路径不受限制

当系统从节点坐标 `XY` 自动计算转角时，浮点误差可能使“直线通过”的 IP 点产生远小于 `0.1°` 的噪声值。若不过滤，这些噪声会被 `CoefficientService.get_gamma()` 的边界逻辑放大为不应存在的弯头损失。

规则如下：

- **坐标计算路径**：`pressure_pipe_extractor._calc_turn_angles`、`siphon_extractor._extract_plan_segments`、`siphon_extractor._extract_plan_feature_points` 都必须在转角 < `0.1°` 时视为直线通过，不生成弯头 / 弯管段，并在计算过程中打印“直线通过，不计弯头损失”的说明。
- **DXF 导入路径**：倒虹吸面板直接导入平面 / 纵断面 DXF 时，角度来自真实几何，不加阈值，按实际值计算。
- `0.1°` 阈值与空间模式中已有的 `spatial_turn_angle > 0.1` 规则保持一致。

### DDR-7：顶部“转弯半径”栏位是统一应用入口，不是隐式全局兜底

顶部栏位用于承载“待应用统一值”，只有用户点击“应用”后，才会覆盖所有真实导入行。原因是 Excel 允许逐行填写不同的转弯半径；如果顶部栏位继续在用户未确认时隐式介入计算，容易把真实导入值和界面临时值混在一起，增加维护和排查成本。

### DDR-8：圆拱直墙型暗涵不走隧洞规则

`暗涵-圆拱直墙型` 只与 `隧洞-圆拱直墙型` 共享几何形状，不共享工程规则。表3应把它作为暗涵家族处理，保留 `B / H_total / theta_deg`，按暗涵净空、暗涵渐变段和普通渠道导出链路执行，避免进入 `xx管` 隧洞摘要或隧洞参数兜底链。

### 12.1 当前实现同步说明（2026-03-21）

- 本轮修复的是纵断面表格末列顶部两行右边框缺失问题，影响入口包括“生成纵断面表格 DXF/TXT”和“导出全部DXF”中的纵断面部分。
- 根因不是“明渠-矩形”“1/3000”等文本超宽，而是普通节点竖线默认只画到 `slope` 行底部；末列右边界又复用了“最后一个节点竖线”，导致当最后一个节点是普通节点时，`building_name` 与 `slope` 两行缺少最右封边。
- 当前实现已改为：仅“最后一个节点 / 最右外框”与特殊进出口节点画满 `line_height`，中间普通节点仍保留短竖线，以维持顶部两行按建筑物段合并显示的既有规则。
- DXF 与 TXT 两条导出链路已同步采用相同竖线策略，避免单独导出与合并导出表现不一致。
