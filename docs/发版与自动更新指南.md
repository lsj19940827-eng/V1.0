# 发版与自动更新指南（正式版单通道）

## 当前实现同步说明（2026-03-20）

- 应用内更新已改为“主程序下载 + 独立更新助手安装”模式；点击“立即安装更新”后，不再弹出 `cmd` / PowerShell 黑窗。
- 安装阶段改为独立品牌化窗口，按“准备安装 / 等待主程序退出 / 校验安装环境 / 备份当前版本 / 解压并应用更新 / 清理临时文件 / 安装完成”展示阶段进度。
- 安装进入“校验安装环境”后，会继续显示细分状态，例如“正在清理上次失败残留”“正在检查写入权限”“正在统计安装目录大小”“正在解压完整安装包或补丁包”“正在校验补丁适用性（x/y）”，避免用户误以为窗口卡死。
- 安装开始时会自动清理当前会话之外的旧 `_update_sessions` 残留，避免上次失败留下的临时目录继续拖住后续更新。
- 安装前会强制检查三项前置条件：
  - 当前项目不能有未保存修改。
  - 当前安装目录必须可写；不再走管理员提权。
  - 当前磁盘剩余空间必须满足“解压 + 回滚备份”最低要求。
- 安装失败时会优先自动回滚到旧版本，并在失败页提供“查看日志 / 打开更新目录 / 重新下载后再试”入口。
- 安装成功后不再自动重启主程序，而是停留在成功页，由用户点击“启动新版本”进入新版。
- 发布包中现在必须包含独立更新助手 `CanalHydraulicCalcUpdater.exe`；构建脚本会自动一并产出。
- 更新助手在安装进行中禁止关闭，避免中断安装或回滚；只有成功页和失败页允许关闭。
- 如果补丁包版本范围不匹配，或本机文件状态与补丁预期不一致，客户端会自动改为重新打开更新对话框并强制本次下载全量包。
- 通用补丁现在只面向近版本链路，当前默认最低覆盖版本是 `1.1.9`；更老版本会直接下载全量包。
- 构建阶段如果发现补丁删除文件过多，或总覆盖量过大，会直接跳过补丁发布，只保留全量包。
- 失败页不再直接展示技术异常，面向用户只显示可操作文案；详细异常继续写入安装日志。

> 更新日期：2026-03-17  
> 当前实现：仅保留正式 Release + 正式 Gist 单通道；用户端不再提供预发布切换入口。

---

## 一、当前实现同步说明

- 自动更新仅检查正式 `version.json`，启动时静默检查和手动“检查更新”都走同一正式源。
- 检查更新弹窗不再向用户暴露“测试（预发布）”通道。
- 如果本机安装过高于正式版的内部构建，正式通道仍保留“降级安装正式版”的兼容入口。
- 发版脚本 `tools/release.py` 只支持正式发布，不再支持 `--prerelease`、`--gist-target test` 或双 Gist 分流。

---

## 二、发布通道规则

| 项目 | 当前规则 |
|------|----------|
| 允许发布分支 | `master` |
| GitHub Release 类型 | 正式 Release |
| 更新清单 | 正式 Gist `version.json` |
| 用户更新入口 | 仅正式通道 |

硬规则：

1. 非 `master` 分支禁止执行正式发版。
2. 发版脚本只写正式 Gist，不再维护测试 Gist。
3. 发布前必须确认工作区没有无关产物被一并 `git add -A`。

---

## 三、正式发版

```bash
git checkout master
git pull origin master

python tools/release.py patch
python tools/release.py minor
python tools/release.py major

python tools/release.py patch -m "- 修复水面线问题\n- 优化更新提示"
python tools/release.py patch --no-bump --tag-suffix rc.20260317.1
```

说明：

- `--no-bump` 仅表示跳过 `version.py` 递增，保留当前版本号继续发版。
- `--tag-suffix` 用于给 tag 增加后缀，例如 `v1.1.1-rc.20260317.1`。
- 发版脚本会自动执行：版本处理、打包、`git add -A`、`commit/tag/push`、创建正式 Release、上传全量包，并在补丁覆盖范围安全时一并上传补丁包、更新正式 Gist。

## 四、手动更新体验

- 程序启动后会后台静默检查正式更新源。
- 点击侧边栏“检查更新”会打开详情弹窗，但不再显示“更新通道”下拉。
- 发现新版本时，只有 `min_patch_version` 范围内的近版本才会优先提示补丁包；更老版本会直接提示全量包。
- 补丁下载失败或补丁安装不适用时，会自动回退到全量包。
- 无论补丁还是全量包，安装窗口在“校验安装环境”阶段都会继续显示细分动作；其中全量包现在也会显示“统计安装目录大小 / 解压完整安装包”的状态。
- 如果用户机器上还留有上次失败的 `_update_sessions` 目录，安装前会先自动清理；清理失败时，窗口会直接提示先关闭软件，仍失败再重启电脑后再试。
- 当前本机版本高于正式版时，可在正式通道执行降级安装。

## 五、`version.json` 字段

| 字段 | 说明 |
|------|------|
| `latest_version` | 最新正式版本号 |
| `download_url` | 全量包下载地址 |
| `patch_url` | 补丁包下载地址，可选 |
| `changelog` | 更新日志 |
| `release_date` | 发布日期 |
| `min_version` | 最低兼容版本 |
| `min_patch_version` | 补丁最低覆盖版本；当前默认只给 `1.1.9+` 提供补丁 |
| `file_size_mb` | 全量包大小 |
| `patch_size_mb` | 补丁包大小，可选 |
| `channel` | 固定为 `stable` |

## 六、首次配置

1. 创建 GitHub Token，并勾选 `repo` 与 `gist` 权限。
2. 在项目根目录创建 `.env`：

```env
GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

3. 在 `repo_config.py` 中配置正式 Gist 的 `GIST_ID`。

## 七、故障排查

- `tools/release.py` 报“只有 master 允许执行正式发版”：
  当前分支不是 `master`，请切换分支后重试。
- 用户端检查更新失败：
  优先检查网络、Gist 可访问性以及防火墙限制。
- 补丁没有出现在正式发布里：
  先看本次构建是否命中了“覆盖范围过大”的兜底规则；命中后会只发布全量包，这是当前的预期行为。
- 用户反馈一直卡在“校验安装环境”：
  先看安装窗口是否已进入“正在清理上次失败残留 / 正在检查写入权限 / 正在统计安装目录大小 / 正在解压完整安装包或补丁包”等细分状态；如果提示旧残留清不掉，先完全退出主程序和更新助手，仍失败再重启电脑后重试。
- 用户反馈版本高于正式版：
  这是历史内部构建兼容场景，可在正式通道使用降级安装回到正式版。
