# xx管纵断面 DXF 导出设计

## 1. 文档信息
- 日期：2026-03-30
- 适用模块：`xx管` 渠道级别下的纵断面 DXF / TXT / 合并 DXF 导出
- 相关入口：
  - `app_渠系计算前端/water_profile/cad_tools.py`
  - `app_渠系计算前端/water_profile/water_profile_dialogs.py`
  - `app_渠系计算前端/water_profile/panel.py`
  - `推求水面线/models/enums.py`
  - `推求水面线/models/data_models.py`

## 2. 背景
- 现有纵断面导出链路默认按“渠类”口径出图，左侧表头和主折线都围绕“渠底高程 / 渠顶高程 / 设计水位”组织。
- 当渠道级别为 `总干管 / 分干管 / 干管 / 支管 / 分支管` 等 `xx管` 级别时，现有模板不符合用户实际用图习惯。
- `xx管` 口径下，纵断面表头应切换到管线专用模板，并且“管中心线高程”来自用户导入的轴线 DXF。
- 仓库中已存在有压管道纵断面 DXF 导入与 `longitudinal_nodes` 持久化能力，本次优先复用现有能力，不新造第二套数据链路。

## 3. 目标
- 在 `xx管` 渠道级别下，为纵断面导出提供固定的 5 行管类模板。
- “管中心线高程（米）”按导入轴线 DXF 的 `Y` 坐标解释为高程，并按节点 `MC` 桩号插值取值。
- `xx管` 模式只画“管中心线”纵断面折线，不再画渠底、渠顶、设计水位折线。
- 允许 `有压管道 / 隧洞 / 定向钻 / 顶管` 进入 `xx管` 导出口径。
- 普通有压管道段不显示“建筑物名称”，仅 `隧洞 / 定向钻 / 顶管` 这些特殊段在“建筑物名称”行出字。

## 4. 非目标
- 本次不改主表中的 `渠底高程 / 渠顶高程 / 设计水位` 业务语义。
- 本次不把“管中心线高程”反写回水面线主表。
- 本次不重构普通渠类纵断面导出逻辑。
- 本次不把 `xx管` 导出拆成完全独立的新模块；优先在现有导出链路中增加清晰分支。

## 5. 已确认的产品决策

### 5.1 触发条件
- 当 `ProjectSettings.channel_level` 为管类级别时，纵断面导出进入 `xx管` 模式。
- 实现上建议封装统一辅助函数，按“当前级别名称属于管类选项”判断，不在导出函数内散落字符串比较。

### 5.2 允许结构类型
- `xx管` 模式允许以下结构参与导出：
  - `有压管道`
  - 所有名称中包含 `隧洞` 的结构
  - `定向钻`
  - `顶管`
- 其余结构一旦混入，禁止按 `xx管` 模式导出，并明确列出冲突行。

### 5.3 固定 5 行模板
`xx管` 模式不再使用当前可配置的 11 项纵断面行，而是固定为：

1. 建筑物名称
2. IP点名称
3. 里程桩号（千米+米）
4. 管中心线高程（米）
5. 管材（管径/米）

### 5.4 建筑物名称显示规则
- 普通 `有压管道` 段默认不在“建筑物名称”行出字。
- 只有 `隧洞 / 定向钻 / 顶管` 这些特殊段在“建筑物名称”行出字。
- 文字按整段居中放置。

### 5.5 管材行显示规则
- 第 5 行继续只表达承压管本体信息，不承担特殊结构类型表达。
- 即便当前段是 `隧洞 / 定向钻 / 顶管`，第 5 行仍写承压管的材质和管径。
- 默认文案先采用紧凑格式，例如：`球墨铸铁管 DN1200`。
- 文字按整段居中放置。

### 5.6 轴线 DXF 规则
- 用户导入的是“管中心线 / 轴线”纵断面 DXF。
- 对二维 AutoCAD 图，读取规则为：
  - `X = 桩号`
  - `Y = 高程`
- 桩号采用“起点自动对齐”：
  - 取 DXF 第一点评估的起点 `X`
  - 自动对齐到该管道进口 `MC` 桩号

### 5.7 高程取值规则
- 导出时，对每个需要出字的节点，按该节点 `MC` 桩号到导入轴线上取“管中心线高程”。
- 取值规则：
  - 命中导入节点：直接取该节点高程
  - 落在线段内：线性插值
  - 落在竖向圆弧段内：按圆弧参数插值
- 只要任一节点桩号超出导入范围，就中止导出，并列出缺失节点。
- 不允许留空导出，不允许端点外推。

### 5.8 数据作用域
- 导入的轴线纵断面数据只用于 `xx管` 导出。
- 不回写水面线主表。
- 不改变现有水力计算字段。

### 5.9 主折线绘制规则
- `xx管` 模式只画“管中心线”纵断面折线。
- 不再画：
  - `渠底高程线`
  - `渠顶高程线`
  - `设计水位线`

## 6. 现有能力复用

### 6.1 已存在的纵断面导入链路
仓库中已存在：
- `app_渠系计算前端/water_profile/water_profile_dialogs.py`
  - `PressurePipeConfigDialog._import_longitudinal_dxf()`
- `倒虹吸水力计算系统/dxf_parser.py`
  - `DxfParser.parse_longitudinal_profile()`
- `推求水面线/managers/pressure_pipe_manager.py`
  - `longitudinal_nodes` 持久化

当前链路已经具备以下能力：
- 读取 `LWPOLYLINE / POLYLINE`
- 将 `X` 解释为桩号、`Y` 解释为高程
- 自动构造 `LongitudinalNode`
- 将结果缓存到 `longitudinal_nodes`

本次不新造第二套导入数据结构，优先复用这条链路。

### 6.2 当前纵断面导出链路
现有纵断面导出核心位于：
- `app_渠系计算前端/water_profile/cad_tools.py`
  - `_draw_longitudinal_profile_table_on_msp()`
  - `_export_longitudinal_txt_to_path()`
  - `export_longitudinal_profile_dxf()`
  - `export_combined_profile_dxf()`

当前导出逻辑中：
- 行定义由 `_PROFILE_ROW_DEFS` 统一维护
- 折线绘制默认画 `bottom/top/water`
- 表头和行内容默认围绕渠类语义构建

本次需要在这里增加 `xx管` 专用分支。

## 7. 目标实现方案

### 7.1 结构与判定层
新增一组纯函数，集中表达 `xx管` 规则：
- 判断当前渠道级别是否为管类级别
- 判断某结构是否允许进入 `xx管` 导出
- 判断某结构是否为“带建筑物名称的特殊段”

建议落点：
- `app_渠系计算前端/water_profile/cad_tools.py`
  - 先落地为本模块私有辅助函数，降低跨模块扩散
- 若后续复用场景增多，再考虑上移到共享层

### 7.2 结构类型扩展
需要扩展以下入口，使 `定向钻 / 顶管` 能进入当前项目数据链路：
- `推求水面线/models/enums.py`
  - 新增 `StructureType` 成员
- 结构类型下拉来源
  - `config.constants.STRUCTURE_TYPE_OPTIONS` 或对应 fallback 常量
  - `app_渠系计算前端/water_profile/panel.py` 的 fallback 列表

说明：
- `隧洞` 类型当前已存在，无需新增枚举，只需纳入 `xx管` 判定口径。

### 7.3 轴线高程求值器
新增一个“按桩号求轴线高程”的纯函数工具，输入：
- 导入后的 `longitudinal_nodes`
- 目标桩号 `MC`

输出：
- 成功：高程值
- 失败：结构化错误信息（越界、段数据异常、空数据）

建议职责：
- 统一处理精确命中
- 统一处理线段插值
- 统一处理圆弧插值
- 统一处理越界报错

建议落点：
- `app_渠系计算前端/water_profile/cad_tools.py`
  - 作为导出专用工具函数
- 若后续计算链路也要复用，再考虑上移

### 7.4 xx管 行模板
不要直接复用 `_PROFILE_ROW_DEFS` 做动态拼装，建议单独维护一份 `xx管` 导出用的固定行定义，原因：
- 它与现有可配置 11 项产品语义不同
- 产品已确认不允许用户在 `xx管` 模式下自由增删行
- 与普通渠类分离后更容易避免回归

建议行定义结构与普通模板保持尽量一致，便于复用版式函数：
- `id`
- `label`
- `header_lines`
- `height`
- `anchor`

## 8. 导出行为设计

### 8.1 表头与行内容

#### 行 1：建筑物名称
- 仅对 `隧洞 / 定向钻 / 顶管` 段出字
- 普通有压管道段不出字
- 同名连续段应合并后居中标注

#### 行 2：IP点名称
- 复用当前 `IP点名称` 生成逻辑
- 保持现有 `IP + 建筑信息` 文案风格

#### 行 3：里程桩号（千米+米）
- 复用 `ProjectSettings.format_station()`
- 保持现有前缀与格式化规则

#### 行 4：管中心线高程（米）
- 对每个导出节点按 `MC` 桩号插值得到
- 保留 3 位小数
- 取值失败则整个导出失败

#### 行 5：管材（管径/米）
- 每段居中出一次
- 默认文案格式：`材质 + 空格 + DN`
- 不重复显示“隧洞 / 定向钻 / 顶管”等特殊结构词

### 8.2 折线绘制
- 普通渠类模式：保持现状
- `xx管` 模式：
  - 仅绘制中心线折线
  - 不绘制 `bottom/top/water` 三条折线

### 8.3 校验与错误提示
导出前需要集中校验以下内容：
- 是否处于 `xx管` 模式
- 是否存在不允许结构
- 每根管是否都有 `longitudinal_nodes`
- 轴线覆盖范围是否覆盖到所有需要导出的节点

错误提示要求：
- 明确指出失败原因
- 尽量列出对应管道名 / 节点名 / 行号
- 不使用模糊提示如“导出失败”

## 11. 风险与控制
- 风险 1：当前代码尚无 `定向钻 / 顶管` 结构类型
  - 控制：先补枚举和下拉选项，再进入导出逻辑
- 风险 2：普通渠类导出与 `xx管` 导出逻辑交叉，容易回归
  - 控制：用独立辅助函数和独立模板分支隔离
- 风险 3：轴线取值逻辑容易在圆弧段出错
  - 控制：先补纯函数单测，再接导出

## 12. 进入实现前的约束
- 先按本设计补测试，再落实现。
- 普通渠类导出逻辑不做顺手重构。
- 若实现过程中发现“定向钻 / 顶管”需要额外的断面参数语义，再单独开下一轮设计，不在本轮偷扩范围。
