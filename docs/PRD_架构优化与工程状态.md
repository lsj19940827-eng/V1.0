# 架构优化与工程状态

更新日期：2026-10-11。适用于当前源码，应用版本仍读取 `version.py`。

## 目标与改动范围

本轮实现架构审查提出的六类改进：保存与依赖失败可见、批量计算服务化、独立工程/表格状态、后台任务边界、共享纯计算与导出分离、重复定义清理及架构回归检查。保持现有断面、水面线、倒虹吸和有压管道计算规则；保留工程兼容字段、界面列顺序、已有高精度保护与编辑交互。

## 数据与界面边界

| 职责 | 实现 | 契约 |
|---|---|---|
| 断面批量计算 | `batch/calculation_service.py` | 输入纯请求数据，返回完整结果、失败记录与过程数据；不导入 Qt |
| 断面编辑组件 | `BatchEditor` | 合并工作区复用编辑控件，独立批量页共用计算服务 |
| 工程文件编解码 | `ProjectCodec` | 校验版本与关键数据形状，迁移旧批量工程，保留顶层未知扩展 |
| 工程会话 | `ProjectSession` | 分开跟踪工程代次与修改修订，快照与界面数据隔离 |
| 水面线状态 | `WaterProfileState / ProfileTableState / ProfileRow` | 节点、结果、设置、原文、精度、来源与行参数集中持有 |
| 节点解码 | `ProfileNodeCodec` | 从纯快照读取节点，公式、原文/精度优先规则与历史一致 |
| 表格适配 | `table_state_adapter.py` | 只在界面线程采集/回填控件，保存和撤销共用完整状态 |
| 专项采用值 | `PressurePipeOverride` | 运行时节点独立字段为依据；旧字典镜像仅兼容读写 |

保留 `QTableWidget` 及既有行编辑接口。本轮采用适配器迁移，不整体更换表格控件；现有行号参数字典作为界面兼容接口，在计算、保存和撤销边界归入带稳定身份的行状态。已有稳定身份随节点/行保存，复制产生新身份，调序不重命名旧计算节点。

## 后台任务与结果归属

1. 界面线程校验输入并复制快照；后台不读取控件，不弹窗。
2. `TaskRunner` 管理工作线程、取消令牌和任务代次；完成、错误与取消回调回到界面线程。结果应用本身失败也进入错误回调。
3. 断面批量和水面线真实按钮采用后台入口，同步内部入口保留兼容。计算中按钮可取消，旧完整结果保留至新任务成功应用。
4. 完成时比较当前输入与提交快照；工程切换使旧代次失效。取消、过期或失败结果不能覆盖当前工程。
5. 水面线在计算阶段之间响应取消；单个阶段内部仍遵循原内核执行。结果表、报告和摘要仍在界面线程更新，不能把本轮描述为所有工作都已后台化。
6. 有压批量已有专用线程继续使用，纳入统一的工程切换与关闭检查。关闭先取消计算回写并等待任务收尾；超时保留窗口，不强制销毁运行中的线程。

## 保存、迁移与错误处理

- 新表格状态 `table_state` 是完整表格恢复依据。旧工程没有该块时执行原迁移路径，下次保存补齐；兼容字段继续输出。无效新状态不能退回旧字段掩盖损坏。
- 完整状态恢复须同时覆盖已保存的隐藏角色和清除未保存的隐藏角色，防止旧节点缓存中的 IP 编号等数据重新渗入当前表格。旧标量 `auto_channel` 迁移为自动补段标记后再附加稳定行身份；其他旧标量角色保留原值，避免静默丢失。
- 长度统计恢复分别验证新 `table_state` 与缺少该块的旧工程；表格数据均可比节点缓存更新，新格式以完整状态为准。
- 嵌入断面、面板、管理器或报告设置失败必须中止保存/恢复，并显示错误。原子写入保护原文件；打开过程中失败恢复原状态，回退再次失败则沿用暂停保存保护。
- 管理器绑定工程路径不读取磁盘。只有打开缺少内嵌配置的历史工程时，编解码边界显式导入同名旁文件；新建和另存为不导入旧配置。
- 工程、配置与工况文件共用 `atomic_json.py`；倒虹吸自动保存失败保留未保存状态并提示。坏独立工况记录诊断，不阻止正常工况载入。
- 自动保存仅产生恢复副本，始终不清除正式工程未保存标记。其界面采集后的 JSON 编码和磁盘写入转后台；旧工程保存完成不得向新工程发送成功状态。正式保存仅能确认同一工程、同一修订的快照。
- 未来版本在更改页面前拒绝，正常同版本顶层未知扩展字段保留。新状态使用版本号约束，不依赖“能读出 JSON 就接受”。

## 共享算法与有压导出

- 平底圆几何下沉到 `calc_渠系计算算法内核/flat_bottom_circle.py`，前端兼容导出同一实现；水力内核不反向依赖前端。
- 正式 `CoefficientService` 共享倒虹吸弯管/折管系数。加载失败明确报错，禁止切换到数值不同的备用表继续计算。
- `calculate_batch` 产生数值快照，`export_batch` 消费快照与导出选项；`run_batch_scan` 保留组合兼容入口。纯计算不创建输出目录或加载绘图/表格导出库；重导出不再次求解，不回查产品目录。

## 维护与验收

- 删除被同类后定义覆盖的旧方法，保留原来实际生效方法的语法树。`tools/check_architecture.py` 检查生产类重复方法和纯模块的依赖方向，允许属性 getter/setter 和声明式重载。
- 历史测试替身由 `test_support/import_guard.py` 隔离。纯 Python 模块映射与属性恢复，真实 Qt 原生模块延迟注册类型保留，避免测试顺序改变结果。
- 单文件回归不能依赖前一个测试预加载正式模型；使用旧模块替身的用例先加载正式模型包，再安装替身。明确检验旧工程迁移的用例须移除 `table_state`；新工程用例直接修改完整表格状态，避免构造两个互相矛盾的数据源。
- 独立回归在工程和用户设置副本中运行，记录每个文件的退出码与用例结果。测试夹具的 Qt 应用强引用仅用于约束应用寿命；控件销毁后的延迟回调须由所属对象上下文取消，不能以应用仍存活代替对象生命周期管理。原生正常关闭另以正式桌面流程验证。
- 独立子进程的导入检查须单独应用正式启动器同等的 Windows WMI 防护；父进程补丁不会自动继承。第二轮曾确认几何桩号三项失败在改造前归档中同样存在；本次继续按现行规则补齐有效暗涵净高，并逐段核对连接段类型和桩号，不改变生产算法，详见 [失败清理记录](qa/failure_cleanup_domain_20261011.json)。
- 必须覆盖正常计算、取消、计算中修改输入、工程切换、计算失败、保存中途失败、恢复回滚、旧工程往返、稳定身份、精度及人工采用值。
- 对比基线是本轮修改开始时的工作区归档，包含此前未提交改动。数值等价核对与交互基准独立记录，不把代码行数下降当性能提升。
- 测试结果及边界见 [架构优化核验](diagnostics/架构优化核验_20261011.md)。源码、离屏真实 Qt 与实际桌面验证分别记录；打包与发布由正式发版流程另行完成。

## Qt 延迟任务与销毁边界

- 延迟提示、置顶、布局调整、启动读取和更新窗口入口均须绑定其所属 `QObject` 上下文。使用 `QTimer.singleShot(延迟, 所属对象, 回调)`，对象销毁时由 Qt 取消待执行回调；不能仅依靠 Python 对象引用仍存在来判断原生控件有效。
- 倒虹吸工况自动保存定时器以面板为父对象，随面板销毁，避免无主定时器残留。面板仍存活时，原自动保存及延迟加载行为保持有效。
- 复核将“断言通过”“未处理回调异常”“进程实际退出码”分别记录。原始探针先处理对象的 `DeferredDelete`，再推进计时器，禁止用 `os._exit` 跳过正常退出。改造前已直接复现被释放的 `MultiSiphonDialog` 和 `QSplitter` 仍被延迟业务访问；修复后同一路径正常结束。
- `tests/test_qt_deferred_lifecycle_unit.py` 同时覆盖存活与销毁分支，并验证真实临时工况自动保存读回。可重复探针为 `tools/qa_qt_exit_probe.py`；证据见 [Qt 退出复核](qa/failure_cleanup_qt_exit_20261011.json)。没有堆栈的历史原生访问冲突不能单凭本次定时器缺陷推定为同一根因。

## 遗留失败清理与验收合同

- 原18项失败逐项核对：复式断面横向范围重复扩张属于显示缺陷，按实际轮廓布置尺寸后修复；其余17项属于不完整测试夹具、读取了用户可变工况或与现行需求冲突的旧断言。校正测试必须保留数值、精度、节点、桩号、绘图范围和编辑历史约束，不能仅改为“未抛异常”或子集判断。
- 复式绘图保留原横向上限及真实比例，逐项检查尺寸可见与不重叠；相同输入的水力结果、轮廓和水位线保持一致，梯形和圆形保护基准保持原图。
- 初始工况测试从独立空目录创建实际面板，并验证初始值、保存内容和再次打开。报告测试区分几何分项与合计展开，同时检查每个真实弯管只参与一次系数计算及高精度输入未被显示舍入。
- 总复验逐文件在独立源码、资料和设置副本中运行，分别记录断言与真实进程退出状态。原生Word分页按既有按需条件单独验收，不为清理失败新增跳过。结果见 [最终逐文件记录](qa/failure_cleanup_suite_20261011.json)，原始失败归因、前后对照和Qt退出证据单独保留。
