## 本轮发现与修复

1. **内部长度缓存误使拓扑失效。** 补段统计把`_stat_length`写入第0列附加数据时触发Qt单元格修改通知，误入用户编辑逻辑，使已准备拓扑失效并增加虚假撤销记录。飞龙已有真实渐变段可兜底继续，但仅补段无渐变段的有效拓扑会被阻断。修复只对内部元数据写回阻断表格编辑信号，并恢复原信号状态。实际68至103行和仅补段案例均回归通过。
2. **重开后Word丢失详细计算过程。** 原工程没有保存详细过程，也未根据已存结果恢复，Word第6章误导出面板初始化的使用说明。新增`detail_report_text`随结果保存、原文恢复；旧工程按已存节点重建报告而不重新计算水力，恢复时间单独标识。没有结果的工程清除旧过程。重开后的实际Word含103节点、两侧闸水位及高程来源，396个OMML公式。
3. **自动补段报告定位不明确。** 原详细报告把沿用邻接IP的桩号直接显示为“桩号”。现自动补段显示自身“中心桩号”和“关联IP桩号”，渐变段使用“关联IP桩号”，常规原节点显示保持原规则。例如节点5的中心2+693.673、关联IP2+687.870，节点17的中心4+472.786、关联IP4+468.723。仅改变报告文字，节点几何、水位和水损不变。
4. **闸前标注与邻接水位文字重叠。** 真实DXF采用微软雅黑字形路径近景渲染时，原闸前标签与紧邻上游普通水位的字框相交。闸双标签原来只按行高缩放，现同时按实际邻接水位文字的保守旋转字框留出水平净距，自适应字高和位置；普通文字、默认设置、水面折线和桩号不变，DXF/TXT及合并导出共用。渠底和渠顶的原字框没有重叠，未调整这两行。

代码改动在`water_profile/panel.py`与`water_profile/cad_tools.py`相关函数。新增回归分别覆盖内部元数据、副作用和门禁，报告定位，保存重开后的真实Word内容，以及近邻闸标签字框。相关契约同步到[推求水面线PRD](../PRD_推求水面线.md)和[纵断面可选行PRD](../PRD_纵断面13项可选行与亭子口模板.md)。本轮尚未发版。
