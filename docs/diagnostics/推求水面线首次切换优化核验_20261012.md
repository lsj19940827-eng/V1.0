# 推求水面线首次切换优化核验（2026-10-12）

## 结论与范围

已复现用户描述的主程序首次进入“推求水面线”约一秒的停顿，并完成源码优化。本机标准 Windows 桌面模式下，首次显示中位耗时由 1279.799 ms 降至 409.263 ms，减少约 68%；再次切换中位耗时由 26.770 ms 至 22.965 ms，保持在几十毫秒。

本轮修改仅涉及工具包按需加载、隐藏公式提示的初始化、嵌入编辑器重复界面的构造，以及对应回归、测量工具和 PRD。水力求解、输入列、工程字段与保存规则不属于本轮改动。工作区原有及同时进行中的闸水位/报告、Rhino 等改动均保留；基线是本轮开始时的工作区，不是 Git HEAD。

源码优化已完成；未执行打包或正式发布。已有安装包需经项目发布流程重新构建后才能包含此修改。

## 根因与处理

1. 主窗口 `PanelRegistry.get()` 在第一次点击导航时同步导入并创建整个水面线页面。工具包 `utils/__init__.py` 原来无条件导出 `ExcelIO`，即使页面只需要数值精度与节点工具，也会加载 `excel_io`、pandas、openpyxl。一次真实点击的分析记录中，这条依赖链累计约 648 ms，占了主要加载时间。
2. `ExcelIO` 改为包级按需导出，首次访问后缓存真实类；保留 `__all__`、完整包入口、顶层 `utils` 别名及原 Excel 后端。既有构建脚本已有两个命名下的显式依赖，无需新增构建项。
3. 默认显示表1时，原来已经创建表3的隐藏公式提示。现在初建仅安装事件过滤器，首次移入有效表头时才导入提示组件并创建卡片，之后复用。卡片及其计时器归属页面；缓存 viewport 身份，避免销毁期间再访问被释放的表头。
4. `BatchEditor` 原来先创建整套隐藏输入/结果操作栏与两组各十项菜单，水面线再创建自己的可见操作栏。共用构造增加 `show_toolbars` 参数，嵌入组件关闭它；独立批量页面保持完整操作栏。表格构造、信号和快捷键共用原实现，隐藏设置和任务/导出状态接口保留。

## 性能证据

使用项目虚拟环境、正式 `MainWindow`、实际导航按钮、默认全局样式和真实管理器；创建可见 Windows 窗口，使用标准 Qt WebEngine，没有切换至 QTextBrowser。测量不执行授权/联网更新预检，只排除这些与导航无关的启动步骤。测试窗口的自动保存定时器停止，不写用户工程，所有正式采样进程正常销毁并以退出码 0 结束。

每个样本来自一个新进程，先让明渠首页显示，再触发水面线导航。首次显示计时包含点击处理和随后一次 Qt 事件处理；10 ms 计时器记录事件循环最大间隔，额外推进事件验证延迟布局。各轮进程重新导入模块，但不清空操作系统文件缓存。性能仍会随本机负载、字体/DPI和存储条件变化。

## 回归与并行改动边界

13个相关测试文件最终去重统计为 104 项通过、2 项失败。通过项覆盖 Excel 依赖拦截及真实工作簿双后端往返、正式/旧包入口身份、实际主窗口首入与公式图片、提示复用及带待执行计时器的销毁、共享批量结果、折叠布局、冻结表编辑与撤销、后台任务、模块注册和延迟工程保存。测试进程分别记录断言与实际退出码；离屏测试使用 QTextBrowser 的样本不作为原生 WebEngine 性能证据。

收尾重跑 `test_water_profile_report_roundtrip_unit.py` 时，两个报告用例原先期望闸前 100.000 m、闸后 99.900 m；共享工作区更新后的计算得到 99.900 m、99.800 m，使旧断言失败。本轮没有修改该测试、水力求解器或它的输入。独立进程对照恢复优化前的 Excel 提前加载、完整隐藏操作栏及公式卡片提前创建，得到完全相同的三节点数值及报告闸水位文字，确认该差异不由本轮导航优化引起。它们不计为通过；本记录也不裁定同时进行中的水力规则修改。
