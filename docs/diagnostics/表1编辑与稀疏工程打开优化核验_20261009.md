# 表1编辑与稀疏工程打开优化核验（2026-10-09）

## 结论与交付范围

本轮在前两轮优化后的工作区继续改进表1交互、输入变更通知、工程打开和工况导航销毁。源码、相关 PRD、复测工具与回归记录已写回，未执行打包或正式发版。

本轮没有改动水力求解内核、搜索精度、输入表列顺序或工程保存格式。性能基线是本轮开始时的工作区，已经包含前两轮优化，不是未修改的 Git HEAD。

## 已解决的问题

1. **选格和批量编辑重复工作**：选格只记录当前文字和行级参数，实际编辑再建立整表历史。粘贴、填充、行操作、Excel导入和撤销恢复暂停逐格信号及重绘，完成后统一通知；Delete保留逐格业务规则，对外只通知一次。异常路径恢复原信号与重绘状态，整次操作可一步撤销。
2. **表1修改标记与旧结果失效不完整**：后端输入变化现在经过完整操作通知传到合并面板，再转发给项目管理器。撤销、重做、流量应用、参数回填和删除最后一行均设置未保存标记，并锁定过期下游结果。取消操作保持原结果状态。
3. **粘贴错列、只读与精度问题**：不再清理掉代表首尾空单元格的制表符；同时粘贴的显式流量保留原文本精度，单独改变流量段仍按原规则同步。整行写入后应用有压类糙率只读状态。后端识别的流量段及撤销恢复同步到可见设置，普通名称编辑不覆盖尚未应用的手动流量。
4. **撤销恢复不完整**：恢复行级固定高度、导入来源、流量段文本、手工加大流量和导入尺寸保留状态；重建表格后恢复当前选格，连续编辑仍能正确撤销。
5. **打开稀疏工程创建全部页面**：立即创建和恢复所有带数据的模块；字段缺失、null或空对象不触发未访问页面创建，现有页面仍重置。未创建的空模块首次访问时使用干净初始值，避免启动示例混入。模块值类型在改动页面前校验，原有失败回退和保存保护保留。
6. **工况标签的销毁后回调**：导航控件持有单次布局计时器，销毁时取消待执行刷新；原先复测中出现的访问已释放控件异常有专门回归覆盖。

## 性能测量

环境为本机 Windows、Python 3.13.3、PySide6 6.11.0。使用真实 Qt 控件的离屏模式，结果页为 QTextBrowser；表格场景为400行、42列的合成数据。每个场景优化前后各5个独立进程，下表取中位数，原始样本均保留。

| 场景 | 优化前 | 优化后 | 耗时减少 |
|---|---:|---:|---:|
| 连续选格100次 | 1038.318 ms | 18.101 ms | 98.26% |
| 粘贴400行、42列 | 358.609 ms | 120.245 ms | 66.47% |
| 读取并恢复仅含明渠数据的工程 | 2608.317 ms | 44.586 ms | 98.29% |

| 重复工作或状态 | 优化前 | 优化后 |
|---|---:|---:|
| 连续选格100次生成的整表快照 | 100 | 0 |
| 一次粘贴的数据变化通知 | 18382 | 1 |
| 一次粘贴对应的撤销步骤 | 1 | 1 |
| 打开仅含明渠数据的工程后已创建的页面 | 8 | 1 |

计时包括操作结束后一次 Qt 事件处理。工程场景包含 JSON 读取、原界面快照及模块恢复，不包含文件选择框、最近项目菜单更新或磁盘写入。所有正式采样进程正常退出；基线采集阶段因销毁回调中止的尝试未计入正式样本。

表格写回文本、行级隐藏参数和流量段文本的摘要在优化前后10份正式样本中完全一致；工程场景5份优化前和5份优化后样本的明渠数据往返均一致。这一结论仅覆盖该对照样本，修正后的只读、空单元格和通知行为另由专项回归验证。最终源码指纹与性能记录对应，先前中间版本的测量保存在记录的 previous_measurements 中。
