# 启动链路说明

更新日期：2026-03-21

本文只回答一个问题：从执行 `main.py` 到用户看到主窗口，这个程序中间到底发生了什么。

关联文档：
- [项目总览](./项目总览.md)
- [模块依赖地图](./模块依赖地图.md)
- [高风险文件清单](./高风险文件清单.md)

## 1. 启动总览

最短路径是：

`main.py` -> `license_checker.py` -> `app_渠系计算前端/app.py` -> `MainWindow` -> 各业务面板 -> `ProjectManager` -> 静默更新检查

```mermaid
flowchart TD
    A[main.py main()] --> B[插入仓库根目录到 sys.path]
    B --> C[设置 Qt High DPI 策略]
    C --> D[license_checker.check_license()]
    D -->|通过| E[导入 app_渠系计算前端.app.main]
    D -->|失败| X[sys.exit(1)]
    E --> F[创建 QApplication]
    F --> G[应用全局字体/样式/Matplotlib DPI]
    G --> H[读取 updater 启动参数]
    H --> I[构造 MainWindow]
    I --> J[创建 Manager 和各 Panel]
    J --> K[初始化 ProjectManager]
    K --> L[默认切换到第一个面板]
    L --> M[启动静默更新检查]
    M --> N[显示主窗口并进入事件循环]
```

## 2. 第 1 段：`main.py` 负责最小启动壳

主入口在 [../main.py](../main.py)。关键步骤如下：

### 2.1 将仓库根目录加入 `sys.path`

- `main.py:10` 定义 `main()`
- `main.py:20` 将当前仓库根目录插入 `sys.path`

作用：
- 确保后续能导入 [../license_checker.py](../license_checker.py)
- 确保能导入 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py)
- 为一批使用中文模块名和裸导入的旧结构兜底

### 2.2 提前设置 Qt 高 DPI 策略

- `main.py:28-29` 调用 `QApplication.setHighDpiScaleFactorRoundingPolicy(...)`

意义：
- 必须在任何 `QApplication` 创建之前执行
- 让 125%、150%、200% 等缩放场景下的窗口和控件渲染更稳定
- 避免授权弹窗等早期窗口与主窗口使用不同 DPI 策略

### 2.3 进行授权校验

- `main.py:35` 导入 `check_license`
- `main.py:36` 根据结果决定是否继续

授权逻辑位于 [../license_checker.py](../license_checker.py)：
- `_DEV_MODE = not getattr(sys, 'frozen', False)`，位于 `license_checker.py:52`
- `check_license()` 位于 `license_checker.py:551`
- 开发态直接放行，`license_checker.py:559-560`

这意味着：
- 源码运行时，授权通常不会阻断开发
- 打包为 exe 后，授权链路才真正参与发布态控制

### 2.4 把控制权转交给前端主程序

- `main.py:42` 导入 `app_渠系计算前端.app.main` 为 `app_main`
- `main.py:45` 执行 `app_main()`

如果这里抛异常：
- `main.py` 会打印异常栈
- 在非 frozen 环境下等待一次回车，便于本地排错
- 最终 `sys.exit(1)`

## 3. 第 2 段：`app.py` 负责创建真正的桌面应用

Qt 主壳在 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py)。

### 3.1 模块加载前的准备

在模块顶层，`app.py` 做了几件会影响全局行为的事：
- `app.py:15` 再次把仓库根目录插入 `sys.path`
- 导入 `ensure_qfluentwidgets_compat()`，保证 `qfluentwidgets` 兼容层先初始化
- 导入 `updater`、`version`、`styles`、各业务 `panel`、`ProjectManager`

这也是为什么 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 是理解全仓库最重要的装配点。

### 3.2 `app.py.main()` 做什么

- `app.py:715` 定义 `main()`
- `app.py:721-724` 在没有现成 `QApplication` 时再次设置高 DPI rounding policy
- `app.py:726` 创建或复用 `QApplication`
- `app.py:727-733` 设置样式、字体与 Matplotlib DPI
- `app.py:735-736` 读取更新助手附带的命令行参数
- `app.py:737-740` 构造 `MainWindow`
- `app.py:741-743` 显示窗口并按需延迟打开更新对话框
- `app.py:743` 进入 `app.exec()` 事件循环

这里读取的更新标记来自 [../updater.py](../updater.py)：
- `updater.py:563` `UPDATE_FLAG_OPEN_DIALOG = "--show-update-dialog"`
- `updater.py:564` `UPDATE_FLAG_FORCE_FULL_PACKAGE = "--force-full-package"`

## 4. 第 3 段：`MainWindow` 装配业务面板与工程能力

### 4.1 主窗口构造

- `app.py:146` 定义 `MainWindow`
- `app.py:149` 开始 `MainWindow.__init__()`

主窗口初始化时会完成：
- 标题、图标和尺寸设置
- 导航栏和 `QStackedWidget` 创建
- 各专业面板实例化
- 项目管理器初始化
- 快捷键绑定
- 默认切换到第一个页面
- 静默更新检查启动

### 4.2 面板装配

`MainWindow._init_ui()` 位于 `app.py:215`，其中最重要的是 `QStackedWidget` 的注册顺序。

当前默认加入主窗口的面板：
- `app.py:419` `OpenChannelPanel`
- `app.py:420` `AqueductPanel`
- `app.py:421` `TunnelPanel`
- `app.py:422` `CulvertPanel`
- `app.py:423` `SiphonPanel`
- `app.py:427` `PressurePipePanel`
- `app.py:428` `WaterProfilePanel`
- `app.py:432-438` 将上述面板加入 `self.stack`

额外注意：
- `app.py:410-416` 先创建 `SiphonManager` 与 `PressurePipeManager`
- 这两个 manager 会被传给 `SiphonPanel` 和 `WaterProfilePanel`
- `app.py:55` 当前 `_EARTHWORK_AVAILABLE = False`
- `app.py:439-441` 说明土石方面板具备接入位，但默认不显示

### 4.3 项目管理器接管生命周期

- `app.py:446` 定义 `_init_project_manager()`
- `app.py:448` 创建 `ProjectManager(self)`
- `app.py:449` 开始把各面板和 manager 实例统一注册给 `ProjectManager`

`ProjectManager` 位于 [../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py)，关键点如下：
- `project_manager.py:32` 项目扩展名 `.qxproj`
- `project_manager.py:39` 自动保存间隔 8 分钟
- `project_manager.py:105` `set_panels()` 统一接管面板引用
- `project_manager.py:166` `_do_auto_save()` 负责自动保存
- `project_manager.py:230` `new_project()`
- `project_manager.py:281` `open_project()`
- `project_manager.py:322` `save_project()`
- `project_manager.py:643` `_load_recent_projects()`

这说明主窗口不是直接自己做保存/打开，而是把“项目状态机”交给独立对象管理。

## 5. 第 4 段：静默更新在窗口启动后进入后台

### 5.1 用户主动打开更新对话框

- `app.py:579` 定义 `_open_update_dialog()`
- 这里会创建 [../app_渠系计算前端/update_dialog.py](../app_渠系计算前端/update_dialog.py) 中的 `UpdateDialog`

### 5.2 启动后自动静默检查

- `app.py:586` 定义 `_start_silent_update_check()`
- `app.py:589` 导入 `SilentUpdateChecker`
- `app.py:590-591` 实例化并启动后台检查线程

更新能力的核心在 [../updater.py](../updater.py)：
- `updater.py:595` `UpdateSession` 用于描述一次更新会话
- `updater.py:641` `_get_main_entry()` 决定更新后如何重新拉起主程序
- `updater.py:764` `create_update_session()` 写入安装会话元数据
- `updater.py:809` `_prefer_windowed_python()` 选择 GUI 友好的 Python 解释器
- `updater.py:1213` `run_update_session()` 执行真正的安装过程

独立安装界面在 [../update_helper.py](../update_helper.py)：
- `update_helper.py:36` 定义安装阶段顺序 `STAGE_ORDER`
- `update_helper.py:76` `_spawn_runner()` 复制/拉起 runner
- `update_helper.py:93` `_launch_main_app()` 安装后重新启动主程序
- `update_helper.py:125` `InstallWorker`
- `update_helper.py:141` `UpdateHelperWindow`

## 6. 第 5 段：窗口关闭时的退出链路

- `app.py:638` 定义 `closeEvent()`

关闭时会做这些事：
- 先询问 `ProjectManager` 是否需要保存未保存内容
- 尝试触发倒虹吸面板自动保存
- 尝试关闭 Matplotlib 资源
- 最终接受或忽略关闭事件

这意味着关闭窗口不是“简单退出”，而是带着项目状态与模块状态收尾的。

## 8. 启动链路中最容易忽略的事实

1. `main.py` 和 `app.py` 都会修改 `sys.path`
2. 授权校验在开发态和打包态行为不同
3. 主窗口在构造阶段就会把多个专业面板一次性实例化
4. 启动后并不会马上弹更新框，而是先做静默检查
5. 更新系统会通过命令行标记反向影响主程序启动行为
6. 当前仓库里土石方模块代码完整，但主壳默认不启用入口

## 9. 启动问题排查顺序

如果程序无法正常启动，建议按下面顺序排查：

1. 看 [../main.py](../main.py) 是否在授权校验前就抛错
2. 看 [../license_checker.py](../license_checker.py) 是否因发布态授权失败退出
3. 看 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 的顶层导入是否因为依赖缺失失败
4. 看某个 `panel.py` 是否因裸模块导入失败导致连锁异常
5. 看 `qfluentwidgets` 或 `Qt WebEngine` 是否在当前环境不可用
6. 看是否由更新助手参数触发了特殊启动分支

## 10. 对后续开发最有价值的结论

- 真正的“启动壳”很薄，复杂度主要集中在 `app.py`
- `MainWindow` 是 UI 装配点，也是多个领域对象第一次汇合的地方
- `ProjectManager` 是程序状态治理中枢，不适合绕开它直接改存取逻辑
- 更新系统与主程序启动参数耦合较紧，改启动逻辑时必须联看 [../updater.py](../updater.py) 和 [../update_helper.py](../update_helper.py)
- 由于存在 `sys.path` 注入和裸模块导入，启动问题有时并不是“模块不存在”，而是“路径上下文不一致”
