## 1. 项目定位

本仓库是一个以 Windows 为主要运行环境的 Python 桌面应用，核心形态是“统一 Qt 前端壳 + 多个水利专业计算子系统 + 更新发布体系”。

从源码入口看，程序先执行 [../main.py](../main.py)，完成路径准备、高 DPI 设置、授权校验后，再进入 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 中的 Qt 主窗口。

目前仓库内至少覆盖这些专业能力：
- 明渠水力计算
- 渡槽水力计算
- 隧洞水力计算
- 矩形暗涵水力计算
- 倒虹吸水力计算
- 有压管道计算
- 推求水面线
- 土石方工程量计算模块（代码已存在，但当前主壳中默认未启用）
- 应用内自动更新与发布

## 2. 一句话架构

可以把它理解为三层：

1. 桌面应用层：`main.py`、`app_渠系计算前端/*`
2. 专业计算层：`calc_渠系计算算法内核/*`、`推求水面线/*`、`倒虹吸水力计算系统/*`、`土石方计算/*`
3. 工程支撑层：`updater.py`、`update_helper.py`、`tools/*`、`tests/*`、`docs/*`

## 4. 程序入口与生命周期

### 4.1 主入口

主入口是 [../main.py](../main.py)。它负责：
- 将仓库根目录插入 `sys.path`
- 配置 Qt 高 DPI 策略
- 调用 [../license_checker.py](../license_checker.py) 做授权校验
- 将控制权交给 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 的 `main()`

### 4.2 主窗口职责

[../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 是主壳与装配中心，主要负责：
- 初始化 `QApplication`
- 统一设置全局字体、主题和 Matplotlib DPI
- 构造 `MainWindow`
- 创建各个业务面板并加入 `QStackedWidget`
- 初始化 [../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py)
- 启动静默更新检查

### 4.3 项目管理

项目文件由 [../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py) 统一负责，关键特征包括：
- 项目后缀为 `.qxproj`
- 自动保存间隔为 8 分钟
- 最近项目通过 `QSettings` 持久化
- 主窗口在启动后会把多个面板实例和 manager 实例统一交给 `ProjectManager`

### 4.4 更新链路

自动更新不只是一段下载逻辑，而是一整套会话机制：
- [../updater.py](../updater.py) 负责版本探测、补丁或全量包选择、下载、解压、覆盖、回滚
- [../update_helper.py](../update_helper.py) 负责独立安装窗口与安装过程托管
- [../repo_config.py](../repo_config.py) 维护 GitHub 仓库、Gist 和下载代理配置
- [../version.py](../version.py) 是版本号单一真相源

## 5. 关键子系统说明

### 5.1 前端壳层 `app_渠系计算前端/`

这是仓库最重要的入口层，既负责界面装配，也承载了一部分业务编排逻辑。典型文件包括：
- [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py)：主窗口与导航装配中心
- [../app_渠系计算前端/styles.py](../app_渠系计算前端/styles.py)：全局样式常量和通用对话框样式
- [../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py)：项目生命周期管理
- [../app_渠系计算前端/update_dialog.py](../app_渠系计算前端/update_dialog.py)：更新检查与更新对话框
- [../app_渠系计算前端/report_meta.py](../app_渠系计算前端/report_meta.py)：导出元数据、项目设置、引用资料
- [../app_渠系计算前端/webview_compat.py](../app_渠系计算前端/webview_compat.py)：Qt WebEngine 降级兼容层

### 5.2 传统算法内核 `calc_渠系计算算法内核/`

该目录下保留了一组直接可导入的专业计算脚本，多个面板会通过 `sys.path` 注入后，直接使用中文模块名导入：
- [../calc_渠系计算算法内核/明渠设计.py](../calc_渠系计算算法内核/明渠设计.py)
- [../calc_渠系计算算法内核/渡槽设计.py](../calc_渠系计算算法内核/渡槽设计.py)
- [../calc_渠系计算算法内核/隧洞设计.py](../calc_渠系计算算法内核/隧洞设计.py)
- [../calc_渠系计算算法内核/矩形暗涵设计.py](../calc_渠系计算算法内核/矩形暗涵设计.py)
- [../calc_渠系计算算法内核/有压管道设计.py](../calc_渠系计算算法内核/有压管道设计.py)

这种结构的优点是复用简单，缺点是包边界弱、可移植性和工具分析能力较差。

### 5.3 水面线子系统 `推求水面线/`

这是仓库中最像“独立领域模块”的部分，目录结构比较清晰：
- `models/`：数据模型和枚举
- `core/`：几何、水力与总计算器
- `managers/`：倒虹吸/有压管道与水面线的共享管理层
- `shared/`：跨模块共享数据
- `utils/`：提取、导入导出等辅助逻辑
- `config/`：常量和默认值

其中比较关键的文件有：
- [../推求水面线/models/data_models.py](../推求水面线/models/data_models.py)
- [../推求水面线/models/enums.py](../推求水面线/models/enums.py)
- [../推求水面线/core/calculator.py](../推求水面线/core/calculator.py)
- [../推求水面线/managers/siphon_manager.py](../推求水面线/managers/siphon_manager.py)

### 5.4 倒虹吸子系统 `倒虹吸水力计算系统/`

倒虹吸前端位于 `app_渠系计算前端/siphon/`，后端逻辑位于 `倒虹吸水力计算系统/`。这是一种前后端分目录的组织方式。

主要后端文件包括：
- [../倒虹吸水力计算系统/siphon_hydraulics.py](../倒虹吸水力计算系统/siphon_hydraulics.py)

### 5.5 土石方子系统 `土石方计算/`

土石方子系统已经具备较完整的独立结构：
- [../土石方计算/__init__.py](../土石方计算/__init__.py) 暴露 `EarthworkProject` 门面类
- `core/` 负责 TIN、断面切割、体积计算
- `models/` 负责地形、线路、断面等数据对象
- `io/` 负责 DXF、CSV、Excel 的输入输出
- `ui/` 提供 Qt 面板

值得注意的是，主壳 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py) 中当前 `_EARTHWORK_AVAILABLE = False`，说明这部分代码已经在仓库里，但不是当前默认可见入口。

## 6. 依赖、配置与运行数据

### 6.1 版本与更新源

- [../version.py](../version.py)：维护 `APP_VERSION`、中文名、英文名
- [../repo_config.py](../repo_config.py)：维护 GitHub 仓库、Gist 和下载代理
- [../updater.py](../updater.py)：读取上述配置执行更新

### 6.2 运行数据

- `data/` 下有默认项目、倒虹吸案例和自动保存数据
- [../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py) 会把自动保存文件写入 `data/autosave/`
- 授权文件由 [../license_checker.py](../license_checker.py) 管理，默认存放在 `APPDATA` 下而不是程序目录

### 6.3 依赖清单

当前没有根级 `pyproject.toml` 或统一 `requirements.txt`，依赖入口主要分散在：
- [../tools/requirements.txt](../tools/requirements.txt)
- [../土石方计算/requirements_earthwork.txt](../土石方计算/requirements_earthwork.txt)

这意味着“运行依赖、开发依赖、构建依赖”还没有完全收敛到一个单一真相源。

## 8. 技术栈摘要

- GUI：PySide6、qfluentwidgets

## 10. 当前快照下最重要的结论

- 这不是单一算法仓库，而是桌面产品仓库
- `app_渠系计算前端/app.py` 是装配中心，很多后续问题都要从这里反推
- `推求水面线/` 是共享度很高的核心域模块
- 更新系统是正式产品能力的一部分，不是附属脚本
- 多处模块仍依赖 `sys.path` 注入和中文裸模块导入，后续重构时必须谨慎
- 超大文件和高耦合面板已经形成维护热点，详见 [高风险文件清单](./高风险文件清单.md)
