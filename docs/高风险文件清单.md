# 高风险文件清单

更新日期：2026-03-21

本文记录当前仓库里最值得谨慎修改的文件与风险模式。这里的“高风险”不等于“写得差”，而是指它们满足以下至少一项：

- 文件过大，改动半径天然大
- 装配和依赖过于集中
- 位于运行入口或产品工程关键链路
- 含有跨模块共享契约
- 已出现明确的环依赖或路径注入
- 存在尚未完成的 TODO / 回退逻辑 / 特殊分支

配套文档：
- [项目总览](./项目总览.md)
- [启动链路说明](./启动链路说明.md)
- [模块依赖地图](./模块依赖地图.md)

## 1. 文件级最高优先级风险

### 1.1 [../app_渠系计算前端/water_profile/panel.py](../app_渠系计算前端/water_profile/panel.py)

为什么高风险：
- 当前约 `6865` 行，是仓库内第二大的项目源码文件
- 既做 UI，也做业务编排，还桥接批量计算、共享数据、倒虹吸多标签对话框
- 顶层就注入两条路径：`water_profile/panel.py:29`、`34`
- 直接依赖 `batch.panel`、`models.data_models`、`models.enums`、`core.calculator`、`shared.shared_data_manager`
- 运行时还会反向触达倒虹吸多标签对话框，`water_profile/panel.py:5679`

改动建议：
- 小步改、先补测试再动逻辑
- 优先抽 helper，不要一次性重切整个文件
- 涉及表格列、导出、同步逻辑时，一定联看相关 UI 测试

### 1.2 [../app_渠系计算前端/water_profile/cad_tools.py](../app_渠系计算前端/water_profile/cad_tools.py)

为什么高风险：
- 当前约 `7086` 行，是仓库内最大的项目源码文件
- 名称看似工具类，实际体量已经接近子系统
- 这类“工具文件膨胀”为大总线后，任何局部修复都可能影响导出、命令生成、CAD 规则或多场景兼容分支

改动建议：
- 不要把它当成普通工具文件随意拼逻辑
- 每次改动前先定位调用点和测试覆盖
- 能抽成独立模块就不要继续堆在同一个文件里

### 1.3 [../app_渠系计算前端/siphon/panel.py](../app_渠系计算前端/siphon/panel.py)

为什么高风险：
- 当前约 `4449` 行
- 同时连接倒虹吸后端、水面线 manager、导出与结果展示
- 存在明确环依赖：与 [../app_渠系计算前端/siphon/multi_siphon_dialog.py](../app_渠系计算前端/siphon/multi_siphon_dialog.py) 互相引用
- 顶层通过 `siphon/panel.py:30` 注入倒虹吸后端路径
- 运行时通过 `siphon/panel.py:1777`、`1981` 再接入 `SiphonManager`

改动建议：
- 凡是涉及多标签、多工况、损失导入的改动，都需要联看 `multi_siphon_dialog.py`
- 如果只是改某一个控件行为，避免顺手把计算或持久化逻辑一起改掉

### 1.4 [../app_渠系计算前端/app.py](../app_渠系计算前端/app.py)

为什么高风险：
- 是主壳装配中心，直接扇出依赖数为当前扫描最高值之一
- 所有主导航面板都从这里首次实例化，`app.py:419-438`
- `ProjectManager`、更新系统、manager 注入都在这里首次接线
- 任何导入错误都可能导致程序整体无法启动

改动建议：
- 把它视为“应用装配容器”，不要把更多业务细节继续往这里堆
- 改启动顺序、窗口构造、参数传递时，要同时联看 [../main.py](../main.py)、[../updater.py](../updater.py)、[../app_渠系计算前端/project_manager.py](../app_渠系计算前端/project_manager.py)

### 1.5 [../updater.py](../updater.py)

为什么高风险：
- 涉及版本比较、下载源选择、补丁和全量包回退、回滚、安装会话落盘、主程序重启
- 这是正式产品能力，不是简单辅助脚本
- 关键结构包括 `UpdateSession`、`create_update_session()`、`run_update_session()`
- 与 [../update_helper.py](../update_helper.py)、[../repo_config.py](../repo_config.py)、[../version.py](../version.py) 高耦合

改动建议：
- 一旦涉及安装目录、补丁 manifest、回滚时机，必须结合测试和本地演练
- 修改命令行标记或安装会话字段时，必须同步检查 `update_helper.py`

## 3. 结构性高风险模式

### 3.1 环依赖

已确认环依赖：
- [../app_渠系计算前端/siphon/panel.py](../app_渠系计算前端/siphon/panel.py)
- [../app_渠系计算前端/siphon/multi_siphon_dialog.py](../app_渠系计算前端/siphon/multi_siphon_dialog.py)

风险：
- 增加初始化顺序敏感度
- 降低可测试性
- 让职责分层变得模糊

### 3.2 路径注入过多

典型位置：
- `main.py:20`
- `app.py:15`
- `open_channel/panel.py:20`
- `pressure_pipe/panel.py:15`
- `water_profile/panel.py:29`、`34`
- `siphon/panel.py:30`
- `multi_siphon_dialog.py:40`、`45`
- `推求水面线/core/calculator.py:16`、`21`

风险：
- 导入成功依赖运行上下文
- IDE、静态分析和类型检查结果会失真
- 后续做包化、插件化或跨平台迁移会更难

### 3.3 中文裸模块导入

典型位置：
- `open_channel/panel.py:71` `from 明渠设计 import ...`
- `aqueduct/panel.py:63` `from 渡槽设计 import ...`
- `tunnel/panel.py:47` `from 隧洞设计 import ...`
- `culvert/panel.py:61` `from 矩形暗涵设计 import ...`
- `pressure_pipe/panel.py:36` `from 有压管道设计 import ...`
- `推求水面线/core/calculator.py:27` `from 矩形暗涵设计 import calculate_rectangular_outputs`

风险：
- 对重命名、包结构整理和自动化工具支持不友好
- 导入失败时排查路径上下文成本高

## 5. 共享契约风险文件

这类文件改动不一定复杂，但影响面会很大。

### 5.1 [../推求水面线/models/data_models.py](../推求水面线/models/data_models.py)

风险原因：
- 是水面线及相关模块共享的数据契约层
- 一旦字段名、默认值、序列化方式变化，可能同时影响 UI、计算、项目保存与导出

### 5.2 [../推求水面线/models/enums.py](../推求水面线/models/enums.py)

风险原因：
- 结构类型、进出口类型等语义集中在这里
- 枚举值一旦变化，会影响条件分支、表格选项、结果导出与兼容逻辑

### 5.3 [../app_渠系计算前端/styles.py](../app_渠系计算前端/styles.py)

风险原因：
- 当前静态扫描下扇入最高
- 任何样式常量或通用对话框行为变化，都可能跨多个面板生效

### 5.4 [../app_渠系计算前端/report_meta.py](../app_渠系计算前端/report_meta.py)

风险原因：
- 多个模块共用导出元数据、引用资料和工程说明
- 改结构时，可能同时影响导出弹窗、文档模板和项目设置

## 6. 产品工程风险文件

### 6.1 [../main.py](../main.py)

风险原因：
- 虽然文件小，但它是全局启动总开关
- 改这里最容易造成“整个程序起不来”

### 6.2 [../license_checker.py](../license_checker.py)

风险原因：
- 同时涉及本地授权、机器码、黑名单、开发态/发布态分支
- 容易出现“开发没问题，打包后有问题”的情况

### 6.3 [../repo_config.py](../repo_config.py) 与 [../version.py](../version.py)

风险原因：
- 一个控制更新源，一个控制版本号真相源
- 改动虽然小，但会牵动发版、更新、下载链路

### 6.4 [../update_helper.py](../update_helper.py)

风险原因：
- 更新安装阶段由它托底
- 它与 `updater.py` 共享会话字段和命令行标记
- 出错往往不是“某个按钮失效”，而是整条升级链路失败

## 7. 测试敏感区域

当你修改下列区域时，最好优先运行对应测试：

| 修改区域 | 优先关注测试 |
| --- | --- |
| 水面线表格/导出/建筑物平面命令 | `tests/test_water_profile_*`、`tests/test_formula_renderer_*` |
| 倒虹吸多标签/工况/示例数据 | `tests/test_siphon_*`、`tests/test_spatial_merger*` |
| 有压管道计算与数据提取 | `tests/test_pressure_pipe_*` |
| 自动更新与安装流程 | `tests/test_updater_*` |
| 主窗口集成与兼容层 | `tests/test_webview_compat_unit.py`、相关 UI stub 测试 |

## 8. 推荐的安全修改策略

面对高风险文件，建议统一采用以下做法：

1. 先定位调用链，不要只看当前文件
2. 先补最小测试，再改实现
3. 一次只改一个风险点，不做顺手大清理
4. 涉及导入、路径、枚举、项目保存格式时，优先把兼容性列出来
5. 改完后至少做一次对应子系统的定向测试

## 9. 如果只能记住三件事

1. `app.py`、`water_profile/panel.py`、`siphon/panel.py` 是当前维护压力最大的三处
2. `updater.py` 和 `update_helper.py` 关系到产品级升级能力，不能按普通脚本改
3. `sys.path` 注入、裸模块导入和超大文件并存，意味着本仓库最需要的是谨慎演进，而不是一次性大拆
