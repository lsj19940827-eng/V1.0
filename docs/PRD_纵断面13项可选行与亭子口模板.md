## 2. 背景与目标
- 纵断面文字导出原本是固定输出，难以适配不同项目模板。
- 用户对“拖拽到底怎么拖才对”反馈较差，尤其是跨列拖拽的学习成本高、容错差。
- 目标是同时解决两类问题：
  - 行内容可配置、可排序、可随项目持久化。
  - 交互足够清晰，第一次使用也能理解正确操作路径。

本次 v1.6 的核心产品决策如下：
- 主交互从“双列穿梭 + 跨列拖拽”升级为“分组式勾选启用 + 已启用项拖拽排序”。
- 拖拽只负责排序，不再承担“启用/移除”的主要学习成本。
- 增加非拖拽补充方式：上移、下移、置顶、置底、右键菜单、快捷键。
- 临时停用重复语义项：
  - `BE(IP文字)`
  - `BK(桩号文字)`
- 注意：底层 13 项定义仍保留，当前仅在“标准配置入口”不暴露 `BE/BK`。

### 2.1 当前实现同步说明（2026-04-01）
- 当前正式入口仍由 `app_渠系计算前端/water_profile/cad_tools.py` 暴露为 `TextExportSettingsDialog`，但活动实现已迁到专用模块 `app_渠系计算前端/water_profile/text_export_settings_dialog.py`。
- `TextExportSettingsDialog` 当前已经显式区分 `standard | xxpipe` 两种模式；本文统一收敛这两套规则，但会按章节分开描述。
- `xxpipe` 模式虽然复用同一个弹窗外壳，但右侧固定为 5 项只读展示，不使用普通模式的“已启用 / 可选项 / 模板 / 排序”交互。
- 新实现不再继承旧的单列表/分组版弹窗类；历史 `_SingleList...`、`_GroupedFluent...`、`_Legacy...` 代码仅保留用于兼容阅读、问题定位和旧实现对照。
- 专用模块内部以 `TextExportSettingsState` 作为唯一状态源，统一管理基础参数、已启用顺序、候选区展开状态以及 runtime 派生结果；启停、排序、模板应用、恢复默认都先改 state，再由单一渲染流程刷新 UI。历史候选搜索字段仅保留兼容读取，不再在界面中暴露。
- 弹窗整体已重构为“左参数、右编辑”的双栏工作台：左栏承载基础参数与实时参数，右栏承载已启用列表和可选项列表，底部操作按钮固定在窗口底部。
- 左栏使用独立 `QScrollArea` 承载基础参数区与实时参数区；右栏不再依赖整窗外层滚动，而是由 `已启用 / 可选项` 两个列表分别承担内部滚动。
- 对话框默认尺寸策略已改为“按分辨率自适应的目标尺寸”：以 `2560 x 1600 -> 2000 x 1400` 作为基准，`1080P` 级别默认约为 `1500 x 945`，`4K` 级别默认约为 `2800 x 1800`；设计基线最小尺寸保持 `1160 x 700`，实际首帧仍会按当前屏幕 `availableGeometry()` 与安全边距裁剪到可用范围内，`QSettings` 中保存的历史小尺寸（如 `960 x 548`）恢复时也会先被钳制到新的可用下限。
- 对话框宽高仍会根据当前屏幕 `availableGeometry()` 自适应裁剪；小屏场景优先保证整窗完整可见与底部按钮可点击，不再依赖“先最大化一次”才能进入可用布局。
- splitter 首帧默认将左栏提升到约 `460px`，并将左栏最大宽度上限放宽到 `620px`；默认打开时基础参数区不再需要先手动拖宽才能正常阅读。
- 左栏分为两段：上方为 5 个可编辑基础参数，下方为实时参数区；实时参数区增加“启用项数 / 内容总高 / 生效竖线高度 / 最小竖线参数”摘要指标。
- 实时参数区只镜像当前已启用行，不再展示旧版固定 7 行输入框，也不再显示“完整行布局明细”大文本框。
- `enabled_runtime_rows` 会按导出顺序实时展示所有已启用可见行，包含 `BD/BF/BJ/BL`；启用 8 项就显示 8 行。
- `生效竖线高度` 单独展示在实时参数区底部；其值来自 `line_height = max(total_height, y_line_height)`。
- 右侧行配置区仍采用“已启用 / 可选项”两段布局：`已启用` 为主区并默认展开，`可选项` 默认展开，四个批量操作仍位于右栏顶部工具区。
- `已启用` 列表继续使用标准可滚动列表；当 `可选项` 区隐藏时，默认高度按当前启用项数自适应增长，最多按 11 项可见高度计算；当 `可选项` 区可见时，优先满足候选卡片面板的可读高度，再由 `已启用` 列表使用剩余空间并在必要时更早进入内部滚动。
- `可选项` 已改为单一候选卡片面板，不再区分“紧凑预览 / quick-add”双模式，也不再显示搜索框。
- `可选项` 剩余 `1 / 2 / 3 / 4` 项时，候选区高度分别按 `1 / 2 / 3 / 4` 张候选卡片自适应；剩余项数 `>= 5` 时固定为 4 张候选卡片高度，并在候选区内部滚动。
- 候选项清空时 `可选项` 区会自动隐藏；候选项重新出现后恢复单一候选卡片面板，并继续沿用“最多 4 张卡片高度”的规则。
- 分组版已补齐单项启用/停用 `InfoBar`、双击切换、空格启停、Delete 停用、右键启停等交互闭环。
- 可选项支持连续逐项勾选加入“已启用”，每次点击后都会立即迁移分组并刷新计数，不再出现仅第一项生效的状态错乱。
- `profile_row_items` 持久化结构、隐藏项 `BE/BK` 规则、亭子口模板规则均保持兼容，不改导出算法与数据结构。
- `panel.py` 的 `_text_export_settings` 默认值已与归一化口径对齐：`y_name=115`、`y_slope=105`。
- `scale_x` / `scale_y` 的产品语义已收敛为严格 `1:N` 比例分母；纵断面图纸坐标统一按“源数据单位 `m` -> 图纸单位 `mm`”换算，公式固定为 `value_m × 1000 / N`。
- 单独 DXF 与合并 DXF 的纵断面绘制链路已共用同一套比例换算逻辑，不再允许两条 DXF 导出链路出现比例口径分叉。
- 本轮同步只修正比例语义与换算实现，不改 UI 字段名和持久化字段名；界面、配置和项目存储中仍继续使用 `scale_x`、`scale_y`。
- 此前实现曾遗漏 `× 1000`，导致非 `1/1` 比例下实体按米值直接除以比例分母而被异常压缩；当前实现已修复，`1:1000` 等图纸比例会按毫米图纸单位正确出图。

## 4. 标准模式弹窗交互：`TextExportSettingsDialog`

补充说明：
- 本章默认都指 `standard` 模式。
- 若渠道级别进入 `xx管` 模式，则弹窗改走固定 5 项只读展示；相关规则见本文第 `10` 章。

### 4.1 整体布局
- 保持 Win11 Fluent 风格。
- 整体采用 `QSplitter(Qt.Horizontal)` 双栏工作台。
- 左栏：独立滚动的参数侧栏，顺序为“基础参数区”与“启用行实时参数区”。
- 右栏：固定的主编辑区，顶部为工具栏，中部为“已启用”主列表区，底部为默认展开的“可选项”区；可选项区始终使用单一候选卡片面板，不再切换双模式。
- `已启用` 与 `可选项` 列表各自独立滚动，列表项数量变化不会再推动底部按钮或相邻卡片发生交叉。
- 底部按钮：`恢复默认` / `取消` / `确定`，固定在窗口底部。
- 目标默认窗口尺寸采用分辨率自适应策略，`2560 x 1600` 档默认约为 `2000 x 1400`，`1080P` 档约为 `1500 x 945`，`4K` 档约为 `2800 x 1800`；最小设计基线为 `1160 x 700`，若屏幕可用区域不足，则首帧按 `availableGeometry()` 自动裁剪；splitter 默认将左栏提升到约 `460px`，但仍允许用户继续拖拽微调。
- 左栏可通过 splitter 拖拽微调宽度；默认状态下基础参数区应已可直接阅读，底部按钮始终固定可见。

### 4.2 参数设置卡片（基础参数可编辑 + 高级参数实时只读）

基础参数（可编辑）：

| 参数 | key | 默认值 | 说明 |
|------|-----|--------|------|
| 字高 | `text_height` | 3.5 | AutoCAD `-TEXT` 字高 |
| 旋转角度 | `rotation` | 90 | 文本旋转角 |
| 高程小数位数 | `elev_decimals` | 3 | 必须为非负整数 |
| 里程桩号小数位数（普通模式） | `station_decimals` | 2 | 仅影响普通模式导出结果里的桩号显示，必须为非负整数 |
| 管中心线高程小数位数（仅 `xxpipe`） | `xxpipe_centerline_elev_decimals` | 2 | 仅影响 `xx管` 模式下“管中心线高程（米）”这一行，必须为非负整数 |
| 里程桩号小数位数（仅 `xxpipe`） | `xxpipe_station_decimals` | 2 | 仅影响 `xx管` 模式下“里程桩号（千米+米）”这一行，必须为非负整数 |
| X方向比例(1:N) | `scale_x` | 1 | 里程方向比例分母；图纸换算按 `value_m × 1000 / scale_x`，例 `1:1000` 输入 `1000` |
| Y方向比例(1:N) | `scale_y` | 1 | 高程方向比例分母；图纸换算按 `value_m × 1000 / scale_y`，例 `1:1000` 输入 `1000` |

补充说明：
- `scale_x`、`scale_y` 的字段名继续保留，当前只修正其产品语义，不做命名迁移。
- 上述 `1:N` 语义适用于纵断面图纸坐标换算：源数据单位为 `m`，导出图纸单位为 `mm`。
- 普通模式点击“确定”时会回写 `text_height / rotation / elev_decimals / station_decimals / scale_x / scale_y`，并继续按实时值回写兼容字段 `y_*`。

启用行实时参数（只读）：
- 采用紧凑三列：`行内容` / `实时Y` / `来源`。
- 只显示当前已启用行；未启用行不再占位显示，也不再出现“未启用/--”固定列表。
- `BD/BF/BJ/BL` 与其它启用行一视同仁，按当前导出顺序直接展示。
- `生效竖线高度` 作为独立一行放在实时参数区底部。
- 不提供手工编辑框，不再保留旧版“完整行布局明细”大文本框或折叠入口。
- 实时参数区和说明文案的高度随内容自然扩张，不再依赖额外几何补救逻辑兜底。
- 点击“确定”时会将兼容字段 `y_*` 按实时值回写，保证导出与界面一致；若对应兼容行未启用，则保留历史兼容值。

### 4.3 高级参数实时映射规则（旧版 Y 坐标兼容）

运行时分为两类结果：
- `enabled_runtime_rows`：仅用于 UI 展示，按当前启用顺序输出 `label / id / text_y / source_label`，覆盖全部已启用可见行。
- `legacy_writeback_values`：仅用于确认时回写旧版兼容字段，继续保留 `y_bottom / y_top / y_water / y_name / y_slope / y_ip / y_station / y_line_height`。

兼容字段回写映射如下：

| 参数 | key | 回写来源 | 对应行未启用时 |
|------|-----|---------|----------------|
| 渠底文字Y | `y_bottom` | `bottom_elev.text_y` | 保留历史兼容值 |
| 渠顶文字Y | `y_top` | `top_elev.text_y` | 保留历史兼容值 |
| 水面文字Y | `y_water` | `water_elev.text_y` | 保留历史兼容值 |
| 建筑物名称Y | `y_name` | `building_name.text_y` | 保留历史兼容值 |
| 坡降Y | `y_slope` | `slope.text_y` | 保留历史兼容值 |
| IP点名称Y | `y_ip` | `ip_name.text_y` | 保留历史兼容值 |
| 里程桩号Y | `y_station` | `station.text_y` | 保留历史兼容值 |
| 生效竖线高度 | `y_line_height` | `line_height=max(total_height, y_line_height)` | 始终写回实时值 |

补充说明：
- `BD/BF/BJ/BL` 只进入 `enabled_runtime_rows` 的界面展示，不新增持久化字段。
- `source_label` 当前用于显示锚点与行高，例如 `中线 / 行高 10`、`底+2 / 行高 40`。
- `panel.py` 中历史初始化值对 `y_name` / `y_slope` 可能存在旧差异，但进入标准流程后，以 `normalize` 和弹窗恢复默认值为准。
- 历史差异的具体值为：
  - `panel.py` 旧初始化（已修正）：`y_name = 112`、`y_slope = 102`
  - `cad_tools.py` 归一化 fallback / 弹窗恢复默认：`y_name = 115`、`y_slope = 105`
- 产品口径要求统一为：
  - 旧项目如果已经持久化了显式值，则按项目值走。
  - 未显式提供时，标准化结果一律回落到 `115 / 105`。
  - 验收与测试应以标准化后的结果为准，而不是以 `panel.py` 的历史裸初始值为准。

### 4.4 行配置卡片

#### 4.4.1 当前主交互
- 分组展示全部可见项：
  - 上方是“已启用”
  - 下方是“可选项”
- `已启用` 是主视觉区，默认完整展开，单列展示全部已参与导出的内容。

## 6. 标准模式排版与绘图规则

### 6.1 比例换算口径
- `scale_x`、`scale_y` 均按严格 `1:N` 解释，输入值表示图纸比例分母，而不是“直接乘除的任意缩放系数”。
- 纵断面图纸绘制时，源数据单位统一视为 `m`，导出图纸单位统一视为 `mm`。
- 换算公式固定为：
  - `sx(value_m) = value_m × 1000 / scale_x`
  - `sy(value_m) = value_m × 1000 / scale_y`
- `scale_x` 负责里程方向，`scale_y` 负责高程方向；两者都必须遵守同一换算口径。
- 单独 DXF 与合并 DXF 的纵断面部分必须共用同一套 `m -> mm` 换算逻辑，避免同一项目在两个 DXF 入口下出现比例不一致。
- 本节只修正比例语义，不改动界面展示字段名和持久化字段名；历史项目配置仍继续使用 `scale_x`、`scale_y`。

### 6.2 行高与文字锚点
- 行高与锚点完全由 `_PROFILE_ROW_DEFS` 控制。
- `_build_profile_row_layout()` 负责根据当前启用项计算：
  - `enabled_ids`
  - `row_layout`
  - `total_height`
  - `line_height`
  - `boundaries`

### 6.3 高度计算
- `total_height = 所有已启用行高之和`
- `line_height = max(total_height, y_line_height)`
- 行从上到下依次排布。
- `boundaries = 各行 top/bottom + {0, total_height, line_height}`

补充说明：
- `0` 是表格底边。
- `total_height` 是“已启用内容真实占高”的上边界。
- `line_height` 是最终竖线与外框的统一上边界。
- 当 `line_height > total_height` 时，顶部会保留一段空白补高带：
  - 范围为 `y ∈ [total_height, line_height]`
  - 这段区域没有内容行，但会保留外框与全高竖线
  - 该设计用于兼容旧项目坐标、避免启用行较少时整体显得过矮
- `boundaries` 排序后既用于左侧表头分隔线，也用于主体区域全宽水平线，二者必须共用同一组 y 值，避免表头与主体错层。

### 6.4 表头区域
- 表头区宽度固定为 40。
- 范围：`x = -40` 到 `x = 0`
- 表头文字中心：`x = -20`
- 单行表头：居中对齐。
- 双行表头：上下行间距为 `text_height * 2.5`

补充说明：
- 左侧表头区的水平线全部使用 `boundaries` 逐条绘制：
  - 从 `x = -40` 画到 `x = sx(0)`
- 表头竖线固定两条：
  - 左边界：`x = -40`
  - 右边界：`x = 0`
  - 纵向范围均为 `y = 0` 到 `y = line_height`
- 主体区域再使用同一组 `boundaries` 从 `x = sx(0)` 画到 `x = sx(last_mc)`，这样表头列和正文区域在所有分隔线位置上完全对齐。
- 双行表头的垂直布局规则为：
  - `line_spacing = text_height * 2.5`
  - `block_h = line_spacing + text_height`
  - 再在当前行高范围内做居中分配，而不是简单贴边摆放
- `station` 的双行表头必须保持：
  - 第一行：`里程桩号`
  - 第二行：`（千米+米）`
  - 不能折叠成单行，否则与既有图纸习惯不一致。

### 6.5 节点竖线高度
- 特殊建筑进/出口节点：竖线取 `line_height`
- 其他节点：取 `short_line_height`

`short_line_height` 规则：
1. 若启用 `slope` 行：`short_line_height = slope.bottom`
2. 若未启用 `slope`，但启用 `building_name`：`short_line_height = building_name.bottom`
3. 两者都未启用：`short_line_height = line_height`

此规则同时作用于：
- DXF 导出：`_draw_profile_on_msp()`
- TXT 导出：`_export_longitudinal_txt_to_path()`

补充说明：
- `short_line_height` 是“普通节点短竖线”的统一高度切断位置，不是某个单独行的文字 y。
- 闸、倒虹吸、隧洞、有压管道、渡槽、暗涵等特殊建筑的进/出口节点，必须保留全高竖线，不能被 `short_line_height` 截断，否则建筑边界不清楚。
- 这条规则同时影响：
  - 表格观感
  - 建筑物名称居中定位时的边界识别
  - 坡降行的中点求解

### 6.6 BC / MC / EC 竖线分段规则
- 当某个 IP 节点满足以下任一条件时：
  - `station_BC != station_MC`
  - `station_EC != station_MC`
- 且当前启用了任一 BC/EC 辅助行时，不能再把该节点简单画成一条完整竖线。
- 系统需改用 `_compute_node_vline_segments()` 按行分段：
  - 属于 BC 语义的行，竖线画在 `station_BC`
  - 属于 EC 语义的行，竖线画在 `station_EC`
  - 其余行继续画在 `station_MC`
- 这样做的目的不是“看起来更复杂”，而是避免：
  - 弯前/弯后文字列与中间列共用一根竖线时产生错位
  - `BD/BF/BJ/BL` 开启后，线框与文字语义不一致
- 如果 `BC/EC` 与 `MC` 没有差异，仍退化成一根普通竖线，避免不必要的分段复杂度。

### 6.7 首列偏移与 DXF / TXT 差异
- 对以下逐节点文字行，首个文本都要做首列偏移：
  - `bottom_elev`
  - `top_elev`
  - `water_elev`
  - `station`
  - 全部 IP 相关行
- 首列偏移公式固定为：
  - `first_col_x_offset = text_height + 1.3`
- 设计意图：
  - 避开起始竖线与首列文字重叠
  - 让最左端第一条文字不贴边
  - 保持与既有图纸出图习惯一致

输出差异说明：

| 场景 | 首个文字 | 非首个文字 |
|------|---------|-----------|
| DXF (`_draw_profile_on_msp`) | `sx(x) + first_col_x_offset` | `sx(x) - 1` |
| TXT (`_export_longitudinal_txt_to_path`) | `sx(x) + first_col_x_offset` | `sx(x)` |

补充说明：
- 这不是笔误，而是当前实现刻意保留的历史差异。
- `DXF` 路径会对后续列额外左收 `1` 个单位，使视觉上更接近既有 CAD 直接出图效果。
- `TXT` 路径保持原始缩放坐标，不额外做 `-1` 修正，以兼容历史命令流。
- `building_name` 与 `slope` 使用分段中点居中放置，不适用本节的首列偏移规则。

## 7. 标准模式数据与文本规则

### 7.1 `building_name`
- 按建筑物分段逻辑输出。
- 自动插入明渠段节点不参与 `building_segments`。
- 特殊建筑内部节点不参与建筑物名称分段，仅进/出口参与。
- 闸类建筑按首节点标注，其余建筑按段中心标注。

补充说明：
- `_get_building_display_name()` 的实现意图非常关键：
  - 不是“凡是特殊建筑节点都标名称”
  - 而是“只允许进/出口节点参与段落划定”
- 原因：
  - 隧洞、倒虹吸、有压管道、渡槽、暗涵等特殊建筑内部往往存在多个 IP 节点
  - 如果这些内部节点也参与 `building_segments`，会把同一个建筑物切碎成多个短段
  - 进而导致 `building_name` 重复、`slope` 重复，甚至两者在视觉上互相挤压
- 明渠、矩形暗涵等直接以结构类型作为显示名。
- 若节点自带 `name`，则采用“名称 + 建筑类别”的合成名，例如：
  - `某某隧洞`
  - `某某渡槽`
- `_merge_segments_across_gates()` 还需要额外处理一种历史规则：
  - 如果两个同名段之间只隔着闸类点状建筑物，则视为同一段落连续，不应被闸拆断。

### 7.2 `slope`
- 复用 `building_segments`。
- 闸类建筑跳过。
- 倒虹吸段、有压管道段输出 `-`。
- 其余建筑取段内第一个有效 `slope_i`，格式化为 `1/N`。

补充说明：
- `slope` 不自行重新分段，而是严格复用 `building_name` 的段结果，避免名称行与坡降行边界不一致。
- 闸类建筑属于点状设施，只用于界定，不参与坡降文本输出。
- 表格竖线继续遵循“中间普通节点不穿透 `building_name` / `slope` 两行”的合并单元格策略，避免顶部两行被切碎。
- 当前实现同步说明（2026-03-21）：
  - 纵断面表格最右侧外框复用“最后一个节点竖线”。
  - 为避免末列顶部两行缺少右边框，`_draw_profile_on_msp()` 与 `_export_longitudinal_txt_to_path()` 当前都将“最后一个节点”视为 full-height 竖线。
  - 因此现状是：中间普通节点仍只画到 `slope.bottom`，特殊进/出节点与最后一个节点画满 `line_height`。
  - 这不是文字越界回避策略；即使“明渠-矩形”“1/3000”等文本较长，末列封边也应由竖线规则保证，而不是依赖文字宽度。
- 段中点并非一律取 `(start + end) / 2`，而是通过 `_resolve_segment_mid_mc()` 结合全高边界竖线做求解：
  - 单点段优先取所在单元格的几何中心
  - 普通长段优先取段落边界中点
  - 这样能减少文字压在线上或跨越特殊建筑全高竖线的情况
- 取坡降值时，段内按顺序查找第一个有效 `slope_i`：
  - 若格式化结果为无效值 `/`，继续向后查
  - 全段都没有有效值时，不输出坡降文本

### 7.3 `top_elev` / `water_elev` / `bottom_elev` / `station`
- 使用 `_build_profile_text_nodes()` 输出。
- 过滤：
  - 渐变段
  - 自动插入明渠段
- 同桩号归并：
  - 取最优代表节点
  - 各高程字段要求非零唯一
- 同桩号冲突：
  - 若出现多个非零且不同值，抛 `ValueError` 中断导出

### 7.4 IP 相关行
- 统一基于 `_build_ip_related_row_records()` 生成：
  - `ip_name`
  - `bd_ip_before`
  - `be_ip_text`
  - `bf_ip_after`
  - `bj_station_before`
  - `bk_station`
  - `bl_station_after`

#### 节点过滤规则
- 渐变段节点排除。
- 自动插入明渠段排除。
- 特殊建筑节点允许进入 IP 相关逻辑。
- 普通节点如与特殊建筑进/出口桩号重合，需要避让，避免重复标注。

#### 命名规则
- 普通 IP：
  - `IP{序号}`
- 特殊建筑进/出口节点：
  - `IP{序号} {合并名称}{进/出}`
- 特殊建筑内部节点：
  - 仅 `IP{序号}`

  - 使用 `station_BC`
  - 普通有转角时可带“弯前”语义
- `BE`
  - 使用 `station_MC`

- `BF`

  - `format_station(station_BC)`
- `BK`
  - `format_station(station_MC)`
- `BL`
  - `format_station(station_EC)`

- `BE/BK` 底层逻辑保留，但不再出现在标准配置列表中。

## 10. xx管 模式专项规则

### 10.1 适用范围与触发条件
- 当 `ProjectSettings.channel_level` 属于以下集合时，纵断面导出进入 `xxpipe` 模式：
  - `总干管`
  - `分干管`
  - `干管`
  - `支管`
  - `分支管`
- `xxpipe` 模式由渠道级别触发，不是由单条节点结构形式触发。
- `xx管` 的 TXT / DXF / 合并 DXF 入口统一以显式 `mode="xxpipe"` 打开 `TextExportSettingsDialog`。

### 10.2 核心结论
- `xx管` 纵断面只允许：
  - `有压管道`
  - 所有名称包含 `隧洞` 的结构
  - `定向钻`
  - `顶管`
- `xx管` 纵断面固定 5 行模板。
- `xx管` 纵断面只画 `管中心线`。
- 普通 `有压管道` 不在“建筑物名称”行出字。
- 仅 `隧洞 / 定向钻 / 顶管` 出现在“建筑物名称”行。

### 10.3 允许结构与导出校验

#### 10.3.1 允许结构
`xxpipe` 模式允许以下结构参与导出：
- `有压管道`
- 任意 `隧洞*`
- `定向钻`
- `顶管`

#### 10.3.2 严格校验
- 导出前检查所有有效节点。
- 只要混入不在允许列表中的结构，就禁止按 `xxpipe` 模式导出。
- 错误提示必须列出冲突行或冲突结构，不能只给出泛化的“导出失败”。

### 10.4 固定 5 行模板
`xxpipe` 模式不再使用普通模式的可配置行，而是固定为：

1. 建筑物名称
2. IP点名称
3. 里程桩号（千米+米）
4. 管中心线高程（米）
5. 管材（管径/米）

### 10.5 弹窗展示口径
- 弹窗右侧只展示固定 5 项，顺序锁定，不提供可选项工作台。
- 这 5 项只用于展示和预览，不允许：
  - 启用/停用
  - 拖拽排序
  - 上移/下移/置顶/置底
  - 套用模板
  - 显示“可选项”分区
- 左侧“启用行实时参数”只镜像这 5 项，并继续使用 `xx管` 专用的实时布局计算。
- 弹窗说明文案应明确表达为“固定模板，仅展示管道纵断面导出的 5 项”。
- 点击“确定”时，只回写基础参数：
  - `text_height`
  - `rotation`
  - `xxpipe_station_decimals`
  - `xxpipe_centerline_elev_decimals`
  - `scale_x`
  - `scale_y`
- 普通模式的 `station_decimals` 不会被 `xxpipe` 固定 5 项回写覆盖；切回普通渠类后应继续保留上次的普通模式桩号精度。
- `xxpipe` 模式下不使用固定 5 项去覆盖普通纵断面的 `profile_row_items`；切回普通渠类后，原有通用行配置应保持不变。
- `xxpipe` 模式不再走“至少启用 1 项行内容”这类普通模式校验，因为固定 5 项始终存在。

### 10.6 各行内容规则

#### 10.6.1 建筑物名称
- 普通 `有压管道` 段默认不出字。
- 只有 `隧洞 / 定向钻 / 顶管` 这些特殊段出字。
- 文本按整段居中。
- 推荐显示文案为“建筑物名称 + 结构简称”，例如：
  - `1#洞段隧洞`
  - `穿路段定向钻`
  - `顶管`

#### 10.6.2 IP点名称
- 复用当前 IP 名称生成逻辑。
- 保持现有 `IP + 建筑信息` 的文案风格。

#### 10.6.3 里程桩号（千米+米）
- 保持现有前缀与“公里数 + 米数”的显示规则。
- 导出链路内单独格式化桩号文本，不修改主界面共用的 `ProjectSettings.format_station()` 口径。
- 普通模式默认保留 2 位小数，并允许用户通过 `station_decimals` 单独调整；同一设置会同步影响普通纵断面、IP 表、合并 DXF 里的 IP 表和 bzzh2 这些普通模式导出结果。
- `xxpipe` 模式默认保留 2 位小数，并继续通过 `xxpipe_station_decimals` 单独调整；该设置只影响 `xx管` 的这一行，不回写普通模式的桩号口径。

#### 10.6.4 管中心线高程（米）
- 对每个导出节点按 `MC` 桩号到轴线上取值。
- 取值顺序：
  - 命中导入节点：直接取节点高程
  - 落在线段内：线性插值
  - 落在竖向圆弧段内：按圆弧参数插值
- 默认保留 2 位小数。
- 用户可在 `xxpipe` 模式弹窗里单独调整 `xxpipe_centerline_elev_decimals`；该设置只影响这一行，不影响普通纵断面的其它高程项。
- 只要任一节点取值失败，本次导出应整体中止。

#### 10.6.5 管材（管径/米）
- 每段居中出一次。
- 即便当前段属于 `隧洞 / 定向钻 / 顶管`，第 5 行仍只写承压管材质和管径。
- 默认紧凑格式：
  - `球墨铸铁管 DN1200`
  - `钢管 DN1000`
  - `玻璃钢夹砂管 DN800`
- `DN` 与数字之间不留空格，但材质和 `DN` 之间保留 1 个空格。

### 10.7 轴线 DXF 规则

#### 10.7.1 导入对象
- 用户导入的是“管中心线 / 轴线”纵断面 DXF。

#### 10.7.2 二维 AutoCAD 口径
- `X = 桩号`
- `Y = 高程`

#### 10.7.3 桩号对齐
- 采用“起点自动对齐”：
  - 取 DXF 第一点评估的起点 `X`
  - 自动对齐到该管道进口 `MC` 桩号

#### 10.7.4 覆盖范围规则
- 轴线覆盖范围必须覆盖到所有需要导出的节点。
- 任一节点桩号落在导入范围外，就中止导出并列出缺失节点。
- 不允许留空导出，不允许端点外推。

### 10.8 数据作用域与绘图规则
- 导入的轴线纵断面数据只服务 `xxpipe` 导出。
- 不回写水面线主表。
- 不改变现有水力计算字段。
- 继续复用现有 `longitudinal_nodes` 持久化字段。
- 普通渠类模式保持现状。
- `xxpipe` 模式只绘制“管中心线”纵断面折线。
- `xxpipe` 模式不绘制 `渠底高程线 / 渠顶高程线 / 设计水位线`。

### 10.8.1 命名定向钻 / 顶管进出口外侧竖线规则
- 命名的 `定向钻 / 顶管` 进点、出点本身仍保留边界竖线。
- 进点左侧紧邻、出点右侧紧邻的普通 `有压管道` 节点，竖线只画到 `IP点名称` 行顶部，不再继续穿入“建筑物名称”行。
- 这些普通节点仍继续显示 `IP点名称 / 里程桩号 / 管中心线高程 / 管材` 文字，不删文字内容。
- 首节点、末节点承担的外框职责保持不变，不能因为本规则把整张表的首尾边框带掉。
- 普通 `有压管道` 的管材分段边界，不再自动升级成整高竖线；整高边界只保留真正需要封边的位置。

### 10.9 实现约束
- 复用已有 `PressurePipeConfigDialog._import_longitudinal_dxf()` 与 `DxfParser.parse_longitudinal_profile()` 能力。
- 复用现有 `longitudinal_nodes` 持久化能力。
- 单独维护 `xx管` 固定模板，不污染普通渠类可配置行定义。
- `TextExportSettingsDialog` 需显式区分 `standard | xxpipe` 两种模式，不能再由弹窗内部自行猜测当前是否为 `xx管`。
- `xxpipe` 模式下保留普通纵断面 `profile_row_items` 快照，不允许把管道固定 5 项回写成通用配置。
- 合并 DXF 与单独 DXF 必须共用同一套 `xx管` 出图口径。

## 11. xx管 相关程序现状与解释口径

### 11.1 哪些结构被当作“有压管道同类”
按当前分支实现规则，以下结构进入“有压管道同类”语义：
- `有压管道`
- `定向钻`
- `顶管`

这层语义的含义不是“在图上都叫有压管道”，而是：
- 会被标记为 `is_pressure_pipe=True`
- 会参与有压流建筑物相关逻辑
- 会复用有压管道计算与配置链路的一部分能力

同时，程序会保留原结构类型文本，不会把 `定向钻 / 顶管` 统一改写成 `有压管道`。

### 11.2 名称与进出口判定

#### 11.2.1 命名的有压管道同类
- 当节点属于 `有压管道 / 定向钻 / 顶管` 且名称非空时：
  - 程序会按“同名 + 结构类别”统计出现次序
  - 第一次出现记为 `进`
  - 最后一次出现记为 `出`
  - 中间节点记为普通断面

#### 11.2.2 未命名的普通有压管道
- 当节点结构为普通 `有压管道` 且名称为空时：
  - 程序允许保留空名称
  - 该行会被视为“逐行独立管段”
  - 不跨表首尾配对
  - `in_out` 会被置为普通断面，而不是自动判成 `进/出`

这意味着：未命名有压管道并非完全不可用，但它不会拥有完整的“成组有压管道”行为。

#### 11.2.3 隧洞 / 定向钻 / 顶管
- `隧洞` 仍属于需要名称和进出口的特殊建筑物。
- `定向钻 / 顶管` 在分支实现里也已进入“需要按组识别”的口径。
- 从当前代码和测试意图看，这三类应视为“需要命名并分进出口”的对象。

### 11.3 输入校验中的名称规则
按当前实现：

- 允许空名称：
  - `明渠-梯形`
  - `明渠-矩形`
  - `明渠-圆形`
  - `有压管道`
- 不允许空名称：
  - `倒虹吸`
  - `隧洞`
  - `渡槽`
  - `矩形暗涵`
  - `定向钻`
  - `顶管`

因此，对用户操作的推荐应写成：
- `xx渠` 中普通 `有压管道`：尽量命名
- `定向钻 / 顶管 / 隧洞`：应命名

### 11.4 有压管道水力计算入口规则
按当前实现：

- 只要表中存在 `有压管道同类` 节点，按钮就保持可点击。
- 但真正能进入计算弹窗还要满足两类前置条件：
  - 拓扑已经准备好，或已插入渐变段
  - 至少存在一个“带名称的有压管道数据组”

若只检测到匿名有压管道行，程序当前提示口径是：
- 这些行按逐行损失计算
- 无需先执行“有压管道水力计算”

若表中没有形成任何命名组，程序会提示：
- `未找到有压管道数据组`

### 11.5 断面汇总与建筑物特性统计
按主线实现与回归夹具意图：

- `xx管` 回归主样例按 3 个流量段组织：
  - 普通有压管道 + 隧洞
  - 普通有压管道 + 定向钻
  - 普通有压管道 + 顶管
- 断面汇总 / 建筑物特性统计列的预期口径为：
  - 只统计 `隧洞 / 定向钻 / 顶管` 的座数与长度
  - 普通 `有压管道` 不记入建筑物特性列

因此，“普通有压管道是承压主体”，“隧洞 / 定向钻 / 顶管是需要单列统计的穿越型建筑物”是当前程序意图的一部分。

### 11.6 行为矩阵

| 场景层级 | 结构类型 | 是否建议填写名称 | 程序是否允许空名 | 是否分进出口 | 是否进入有压管道分组计算 | 是否在 xx管 建筑物名称行显示 |
| --- | --- | --- | --- | --- | --- | --- |
| xx渠 / 通用预处理 | 有压管道 | 建议 | 允许 | 命名时分；匿名时不分 | 命名时进入；匿名时不进入 | 不适用 |
| xx渠 / 通用预处理 | 定向钻 | 必须 | 不允许 | 分 | 进入 | 不适用 |
| xx渠 / 通用预处理 | 顶管 | 必须 | 不允许 | 分 | 进入 | 不适用 |
| xx渠 / 通用预处理 | 隧洞 | 必须 | 不允许 | 分 | 不走有压管道分组，但属特殊建筑物 | 不适用 |

### 11.7 已知不一致与解释口径

#### 11.7.1 通用 special-structure 口径 与 xx管 导出口径并不完全一致
- 主线通用函数中，`有压管道` 仍被视为特殊建筑物的一类。
- 这会影响：
  - 通用纵断面建筑物名称段划分
  - 平面建筑物名称导出
  - 部分依赖 `进/出` 的逻辑
- 但 `xx管` 专用导出层已经额外收紧为：
  - 普通 `有压管道` 不显示建筑物名称
  - 只显示 `隧洞 / 定向钻 / 顶管`

因此，本文将两者解释为：
- 通用层：偏“数据识别 / 特殊建筑物处理”
- `xxpipe` 导出层：偏“最终图面表达”

#### 11.7.2 分支已把 定向钻 / 顶管 纳入有压管道同类，但主线尚未完全全域统一
- 分支代码已在预处理、分组提取、共享数据透传、批量占位行等环节把 `定向钻 / 顶管` 纳入“有压管道同类”。
- 主线 `xx管` 导出与测试也已支持它们出现在导出链路中。
- 但若仅看当前 `master` 某些通用函数，仍可能看到以 `有压管道` 为主语的旧表述。

本文口径采取：
- 在需要判断“是否走承压管逻辑”时，把 `定向钻 / 顶管` 与普通有压管道并列描述。
- 在需要判断“图面建筑物名称是否显示”时，把 `定向钻 / 顶管` 与 `隧洞` 归为命名建筑物。

### 11.8 团队简化规则
1. `xx管` 纵断面里，普通 `有压管道` 不命名，也不靠图面区分进出口。
2. `xx管` 纵断面里，只有 `隧洞 / 定向钻 / 顶管` 需要命名，且这三类按进出口组织。
3. `xx渠` 或通用表3处理中，普通 `有压管道` 最好命名；不命名虽然允许，但只会按逐行独立管段处理。
4. `定向钻 / 顶管` 在程序语义上已经属于“有压管道同类”，但在图面和统计上仍保留各自工艺名称。

## 12. 验收标准

### 12.1 `standard` 模式
- 用户不需要理解跨列拖拽即可完成启用与排序。
- 首次进入即可理解主操作方式。
- 已启用项顺序与导出顺序一致，且界面有顺序号反馈。
- 不使用拖拽时，仍可通过按钮、右键、快捷键完成排序调整。
- 左栏参数区为独立滚动侧栏，基础参数与启用行实时参数分为上下两个区域展示。
- 实时参数区严格镜像当前已启用行：启用几项就显示几行，`BD/BF/BJ/BL` 也必须出现。
- 不再显示旧版固定高级参数输入框与行布局明细大文本框。
- 默认 7 项时，左栏基础参数区与右栏主列表都不需要先手动拖 splitter 才能进入可工作状态。
- `可选项` 默认展开，且不再显示搜索框；默认 `7 项已启用 + 4 项可选` 场景下，候选区必须完整显示 4 张候选卡片，底部按钮始终可见。
- 当可选项剩余 `3 / 2 / 1` 项时，候选区高度必须分别稳定到 `3 / 2 / 1` 张候选卡片，卡片不得出现半张、细条状挤压或伪滚动条。
- 当可选项剩余 `>= 5` 项时，候选区固定为 4 张卡片高度并在自身内部滚动；候选区可见时，“已启用”主列表应改为动态使用剩余空间并允许更早进入内部滚动。
- 默认 7 项、首帧 11 项、`7 -> 11 -> 7 -> 11` 反复切换三类场景下，左右栏、各列表区与底部按钮区都不得发生交叉重叠。
- 小屏或恢复历史较小窗口尺寸时，允许左栏滚动和列表内部滚动，但不允许通过补丁式几何刷新才能恢复稳定布局。
- `BE/BK` 不再出现在当前配置列表中。
- `BD/BF/BJ/BL` 保留可配置能力。
- 历史底层导出逻辑保留，不做硬删除。
- 配置可随项目保存并恢复。
- 不改 UI 字段名与存储字段名，继续沿用 `scale_x`、`scale_y`。
- 单独 DXF 与合并 DXF 的纵断面部分都必须按严格 `1:N` 语义应用 X/Y 比例：源单位 `m`、图纸单位 `mm`、公式为 `value_m × 1000 / N`。
- 非 `1/1` 比例下，里程与高程实体不得再出现“少乘 `1000`”导致的异常压缩。

### 12.2 `xxpipe` 模式
- `xxpipe` 模式下表头固定为 5 行。
- `xxpipe` 模式下弹窗右侧固定展示 5 项，不出现可选项、模板按钮和排序操作。
- 结构校验允许 `有压管道 / 隧洞 / 定向钻 / 顶管`，其余拦截。
- 建筑物名称仅在 `隧洞 / 定向钻 / 顶管` 段出现。
- 管中心线高程按轴线 DXF 插值得到。
- 里程桩号默认保留 2 位小数，并允许用户单独调整；普通模式使用 `station_decimals`，`xxpipe` 使用 `xxpipe_station_decimals`，两者彼此独立。
- 管中心线高程默认保留 2 位小数，并允许用户单独调整；普通纵断面继续沿用 `elev_decimals`。
- 导入范围不足时禁止导出。
- 图上只画中心线，不画渠底、渠顶、水位三线。
- 命名 `定向钻 / 顶管` 进出口外侧紧邻的普通 `有压管道` 节点不画竖线，但进出口边界线、首尾外框和文字内容必须保留。
- `xx渠` 中普通有压管道的文档口径明确为“尽量命名”。
- `xx管` 中普通有压管道的文档口径明确为“不在建筑物名称行命名”。
- 确认时只回写基础参数，不覆盖普通模式的 `profile_row_items`。
