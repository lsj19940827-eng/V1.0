# 已废弃：`tools/release.py` 预发布双通道改造方案

> 状态：历史归档，2026-03-17 起不再作为当前实现依据。  
> 原因：仓库已收敛为“正式 Release + 正式 Gist”单通道，不再维护测试 Gist 或用户侧预发布入口。

## 当前真实状态

- `tools/release.py` 仅支持正式发布，不再支持 `--prerelease`。
- 更新清单只写正式 `GIST_ID`，不再存在 `GIST_ID_TEST`。
- 客户端检查更新弹窗不再提供“测试（预发布）”切换。
- 通用补丁当前只对近版本开放，默认最低补丁版本为 `1.3.0`；更老版本直接下载全量包。
- 如果补丁删除文件过多、总覆盖量过大，或补丁包接近完整包，构建、正式发版和回补 patch 阶段都会直接跳过补丁，只发全量包。
- 更新包现在会带 `download_sha256 / patch_sha256`，客户端下载完成后先验包；补丁应用完成后还会按 `target_files` 再做一次目标版本验收。
- `siphon_autosave.json`、`data/autosave/` 和 `*_autosave.qxproj` 已从 manifest、patch diff 和补丁严格哈希校验里排除，成功安装后也会保留。
- 正式发版后会自动固化 `.release-snapshots/` 快照；后续回补 patch 只能基于这份快照，并覆盖 `--min-version` 到目标版本前的全部正式基线，不再允许直接拿漂移过的本地 `dist` 或手工改过的 manifest 回补。
- `1.3.0+` 用户优先补丁；补丁下载、校验或安装失败时，安装助手会自动改用完整安装包继续更新，只有完整包也失败才显示失败页。
- 安装开始时会先清理旧 `_update_sessions` 残留；`validate` 阶段会继续显示“正在清理上次失败残留”“正在校验更新包完整性”“正在检查写入权限”“正在统计安装目录大小”“正在解压完整安装包或补丁包”“正在校验补丁适用性（x/y）”，并在大文件哈希时显示单文件百分比；旧残留清理失败时会直接提示先关闭软件、仍失败再重启电脑。
- 正式打包使用根目录多尺寸 `icon.ico`；该图标由蓝色新 Logo 本体生成，不内嵌白色圆角底框，客户端启动时也会把同一图标设置到 `QApplication` 和主窗口，Windows 任务栏、标题栏和弹窗图标保持一致。
